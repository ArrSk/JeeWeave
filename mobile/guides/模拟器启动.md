# 在这台电脑上体验 Android 版

模拟器、adb 和 Android15 镜像已下载在项目 mobile/.cache/toolchain；不用再次安装 Android Studio。测试包生成位置为 `mobile/.cache/verification/JeeWeave-native-testbed.apk`，安装后叫“几微验证”，使用独立资料。10月27日已清理旧测试包与AVD；源码的新界面仍待用户确认后再打包。工具和系统镜像保留，AVD会按当前项目目录重新创建。

启动器直接使用 Windows 自带的 cmd 调用模拟器，不依赖 `pwsh`、PowerShell 或脚本执行策略。直接双击即可，不需要在终端输入命令。下方重新下载工具和构建 APK 的开发命令仍使用 PowerShell 7，与日常启动模拟器分开。

## 第一次需要设置 Windows

1. 按 Ctrl + Shift + Esc 打开任务管理器，进入“性能 → CPU”，检查“虚拟化”是否为“已启用”。如果未启用，需要重启进入电脑 BIOS，开启 Intel Virtualization Technology / VT-x 或 AMD SVM；入口按电脑厂商说明操作。
2. 打开 Windows 开始菜单，搜索“启用或关闭 Windows 功能”。勾选 **Windows Hypervisor Platform** 对应的系统项目（中文版通常显示“Windows 虚拟机监控程序平台”），点确定，然后重启电脑。不要只勾选名称相近的“虚拟机平台”。
3. 重启后双击 [mobile/启动模拟器.cmd](../启动模拟器.cmd)。启动器会先检查硬件加速，不可用时给出原因并停止，不会再反复尝试此前失败的软件 CPU 模式。

以上 BIOS/Windows 设置需你亲自确认，本项目不会自动启用它们或安装系统驱动。[Android 官方加速说明](https://developer.android.com/studio/run/emulator-acceleration)要求 Windows 上启用可用的硬件虚拟化；软件 GPU 只是图形渲染方式，不能替代 CPU 加速。

## 打开几微验证

1. 保持启动器窗口打开，等待模拟器显示 Android 桌面；第一次通常较慢。
2. 从文件管理器把 `JeeWeave-native-testbed.apk` 拖进模拟器窗口，等待安装完成。
3. 打开应用列表，点击“几微验证”。进入设置开启开发者模式，可导入虚构示例。这里的资料与桌面版和正式手机应用独立。
4. 验证键盘输入、底部操作、系统返回、课表切换和文件导入导出。学校账号、验证码仍由你自己输入。
5. 体验结束关闭模拟器窗口即可；下次再次双击启动器，原模拟器资料保留。卸载测试应用会删除它的私有资料。

本轮只做电脑手机尺寸预览和测试包编译，没有把这些检查称作 Android 原生实测。此前本机加速检查未通过，软件 CPU 模式也没有成功启动；完成上面的 Windows 设置后，仍需实际启动确认。

## 仍然打不开时

- 在命令提示符切到 mobile 文件夹，运行 `启动模拟器.cmd -CheckOnly`，保留显示的完整加速状态。
- 出现明显的图形驱动错误时，可运行 `启动模拟器.cmd -Gpu auto` 尝试系统 GPU；默认是软件图形渲染，CPU 始终要求硬件加速。
- 完整启动日志位于 mobile/.cache/verification/emulator-ui-*.log。不要自行删除模拟器资料来反复尝试，先查看错误。
- 机器换位置或工具缓存被清理后，运行 `pwsh -NoProfile -File mobile/setup-tools.ps1 -AndroidTests` 重新准备官方工具；新电脑重新构建测试包：`pwsh -NoProfile -File mobile/build.ps1 -TestBed`。

启动器只选择项目自己的 `jeeweave-phone` 虚拟设备，不查询或安装 USB 手机上的应用，也不改系统代理、PATH 或 Windows 功能。
