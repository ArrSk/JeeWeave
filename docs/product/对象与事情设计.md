# 围绕一件事组织几微

状态：2026-10-19 设计、2026-10-20 更新。本文是长期方向；Desktop 已提供对象视图 Beta（课程/项目/主题、手动主归属、聚合排课/事项/网页及双向跳转）。单次课布置来源、多段独立投入、多相关对象和通用文本用途归类尚未实现；具体边界见[桌面说明](../../desktop/README.md)。

## 用户真正想解决的问题

一条“周四前交作业”告诉用户要做什么，却可能丢失它属于哪门课、为什么要做、老师具体要求什么、还剩哪些步骤。把上课、作业、资料和费用分别放在功能页后，用户不得不在脑中重新把它们拼起来。

几微应当帮助用户推进一件有来由、有结果的事情。课程表、待办、计划、日历提供不同的查看和处理方式；用户在每个入口都能回到这件事的背景。

## 先把四种含义分清楚

| 用户看到的内容 | 含义 | 例子 | 生命周期 |
| --- | --- | --- | --- |
| 对象 | 长期组织相关内容的主题 | 本学期高等数学、课程项目、一次旅行 | 持续存在，可归档 |
| 一次活动 | 对象在某个时间的一次发生 | 周一这节高数、周三项目讨论 | 有自己的时间和发生状态 |
| 要办成的事 | 有结果或完成标准的工作 | 交出第 5 次作业、完成课程报告 | 可完成、取消或重新打开 |
| 行动与安排 | 为办成这件事采取的步骤、投入的时间 | 做第 1–4 题；周二晚上做题 | 可以有多步、多段时间 |

“对象”是产品组织语言，不要求用户每次先建一个文件夹。“一件事”也可以很小：买一本教材本身就能完成，不必强制拆出“查价格、打开商店、付款”三个任务。

“事件”容易同时指整件事和某次发生，界面尽量使用明确名称：**课程、这节课、作业、项目、安排**。“事情详情”承担关联入口，不把所有内容都称为事件。

## 用两门课走一遍

```text
高等数学 · 本学期
  ├─ 周一这节课：讲导数（课表中的一次活动）
  ├─ 第 5 次作业：提交导数练习（要办成的事）
  │    ├─ 为什么：巩固本节导数方法；完成标准：按要求提交
  │    ├─ 来源：老师本节课的要求、原通知
  │    ├─ 需要做：做题 → 核对 → 提交（可选步骤）
  │    ├─ 执行：周二 19:00–20:00；周四 18:00–18:30
  │    └─ 截止：周五 20:00
  ├─ 教材与课堂资料
  └─ 教材费用（记账接入后）

程序设计 · 本学期
  └─ 实验报告：周三做实验，周六整理，周日截止
```

作业属于整门高数，也能注明由周一这节课布置。教材通常属于整门课程；一次实验的耗材才可能属于具体实验。关联粒度由内容决定，不能把一个学期的费用挂到今天每节课下面反复出现。

作业截止可以晚于上课时间，执行安排可以分布在多天；不要求它位于课表节次内，也不因上课改时间而自动改截止日。实验报告和导数练习各有自己的目标与时间，不共享一份“课程待办完成状态”。

## 页面怎样分工

| 入口 | 首先回答的问题 | 共同保留的上下文 |
| --- | --- | --- |
| 课程表 | 什么时候在哪里上哪节课 | 课程对象、这节课、相关作业与资料 |
| 事情详情 | 这件事为什么做、怎样算完成、现在推进到哪 | 对象、来源、结果、步骤、安排、资料 |
| 待办 | 下一步需要采取什么行动 | 所属事情和课程，可直接回到背景 |
| 计划 | 怎样分配执行时间、阶段与重复安排 | 指向原事情，调整时间不复制完成状态 |
| 今天工作台 | 今天要推进哪些事，有哪些约束 | 先按事情组织，再显示今天的步骤和安排 |
| 日历 | 哪些时间被占用，哪些事情即将截止 | 活动、执行时段、截止标记各自明确 |
| 记账、资料 | 这笔钱/这份内容是什么、服务哪件事 | 回到关联对象；以后实现时接入 |

今天页的示例不是三张没有关系的“做题 / 看答案 / 提交”卡，而是：

> 高等数学 → 第 5 次作业
>
> 为了巩固导数方法；周五 20:00 截止。
>
> 今天 19:00–20:00 做第 1–4 题。查看要求 · 查看全部安排 · 打开课程。

工作台以“事情”为一级组织，但仍允许独立待办和无日期事项。没有明确目标时可以先收集，之后再关联，不强制填写目的。

## 点击与跳转

1. 点课程卡仍能查看/编辑课程；详情增加“整门课程 / 这节课”的明确切换，避免把长期资料只挂到单次课。
2. 在课程或某节课内添加作业，预填所属课程；如果从单次课进入，来源额外记录这节课。用户可更改归属。
3. 从待办、计划或日历打开同一件事，看到相同的名称、目标、状态与来源；面包屑可以返回课程。
4. 给这件事安排另一段时间，只增加执行时段，不再生成一条同名待办。
5. 查看教材、通知或费用时可以返回关联事情；跨多个对象的资料保留一个原件、多处引用。

第一版不必新增占满侧栏的“事件管理”模块。先在已有课程与事项入口提供详情和归属，验证跳转确实有用，再决定是否需要独立对象总览。

## 怎样算完成

- 办成一件事，以结果为准，例如“已按要求提交作业”。用户可以直接完成简单事情，不必先把所有可选步骤勾完。
- 步骤都完成时可以提示“是否完成这件事”，不自动宣告成果已验收；用户也可以选择跳过或撤销步骤。
- 上完这节课，不会完成该课程全部作业；交完这次作业，不会完成整门课。
- 时间段过去只说明安排结束，不能推断事情做完。记账完成也不能推断教材已经收到。
- 重复活动只改变本次状态；无期限的课程/主题使用归档，有限目标才使用完成。

## 文本、通知和资料也按“对象 + 用途”组织

同一份文本有两个独立维度：**它与谁有关**，以及**拿它做什么**。

| 文本 | 关联对象 | 用途 | 可以进一步提取什么 |
| --- | --- | --- | --- |
| 老师发布的作业要求 | 高数、第 5 次作业、可选本次课 | 行动要求 | 提交内容、截止、提交方式 |
| 导数讲义 | 高数 | 学习参考 | 主题索引、与作业相关段落 |
| 课程项目评分标准 | 程序设计、课程项目 | 验收标准 | 必交成果、评价规则 |
| 教材收据 | 高数、教材购买 | 费用凭据 | 金额、日期；记账接入后确认 |

正文原件、摘要、行动草稿分开保存；摘要不替代原要求，每个建议都能回到依据。对象与用途允许多选，主归属只有一个，不能复制同一文件到每个模块制造多个原件。不确定时进入“待归类”，保留用户手工调整与独立文本。

第一阶段只需要手动关联与本地规则。外部模型、聊天监听、记账和笔记编辑器分别排期，不作为完成此设计的前置条件。

## 改造后的最低验收

1. 两门课各有两次作业，课程内只显示正确归属；一个作业的两段执行时间仍指向同一事情。
2. 从课表 → 作业 → 原要求 → 返回课程，背景和筛选位置不丢失；待办与日历也能到达该作业。
3. 从不同入口完成同一事情，其他入口同步；完成一节课、一个步骤或一个时段不会误完成其他内容。
4. 课程调时、停课或归档后，作业和资料仍可找到；跨两门课的项目不会被重复完成或重复计费。
5. 旧独立待办不被强制归类；旧 ID、周次、阶段、重复完成、日期和备份恢复全部保留。
