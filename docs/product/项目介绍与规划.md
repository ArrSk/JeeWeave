# 几微 · JeeWeave 项目介绍

更新：2026-10-30。本文说明产品定位与长期方向；当前实现和验证范围以[交接说明](../HANDOVER.md)及各端README为准。

## 设计初衷

JeeWeave · 几微是本地优先、可通过插件扩展的个人工作台，以对象与事情连接零散信息、时间安排和行动，帮助用户理解来由、推进目标并积累经验。

用户遇到的困难是：课程、作业、笔记和费用分别存放后，需要在脑中重新拼起它们的关系。几微希望保留“为什么做、与谁有关、怎样算完成、今天怎样推进”，让不同入口都能回到同一件事。名字里的“几微”强调细小但重要的日常，“Weave”表示把零散的信息和行动织回相关背景。

课程与学习是首先落地验证的场景，课程表是一个切入口。项目后续也应容纳个人项目、锻炼、旅行及其他生活主题；新增能力是否值得做，取决于是否帮助用户记录、理解或推进事情，不以能否挂在课表下作为条件。

## 内容怎样连接

对象是持续组织相关内容的课程、项目或主题；事情是希望办成的结果；活动是某个时间的一次发生；行动与安排是推进事情的步骤和投入时间。它们通过稳定引用关联，完成状态各自明确，原内容保留一份。详见[对象与事情设计](对象与事情设计.md)。

例如“提高身体素质”可以关联篮球课程、每周锻炼安排与训练笔记；未来的相关支出也可由记账能力接入。完成一次锻炼不会自动完成这个长期主题。多对象关系、记账等仍属于后续设计，不因例子出现就视为已实现。

用户可以从一段想法、一份资料、一个事项或一次活动开始。无需先建对象、填目的或拆步骤；笔记、独立待办、无日期内容和待归类资料始终可单独使用。

## 底层怎样支持

宿主统一插件运行、依赖、公共接口、事件、导航与资源清理；数据机制维护原记录、稳定身份、持久化和恢复。业务插件分别负责课程、事项、笔记、提醒等能力，通过公共服务连接。今天、日历与对象视图汇集原内容，不再维护一套同名记录与完成状态。

AI助手是调用公共能力的可选入口，先拟草稿再确认执行；不用AI仍能手动完成核心操作。平台层处理Windows、Android及浏览器各自的文件、窗口和系统能力。职责和实际边界见[架构说明](../ARCHITECTURE.md)。

## 当前基础与后续边界

Windows 0.4.0已有课程表、教务导入、统一事项、今天、日历、笔记、对象Beta、查找、全局助手和独立提醒，内置业务已接入插件宿主。对象当前主要支持手动主归属，不代表完整多对象网络。

Android已有Beta包，最新版桌面能力已移植至本地源码预览；等待体验确认，APK尚未随之更新。Web/PWA仍是独立客户端，资料不会自动跨端同步。真实系统输入、后台通知与旧设备兼容需要分别验收。

记账、完整知识库、多对象关系、跨设备同步和安全安装第三方插件等仍为后续方向。群消息接入继续暂停，保留原代码与资料。内置插件可开关不等于已经具备第三方插件安全沙箱。

## 最终愿景与开发约束

让用户能沿着“原始信息 → 相关对象 → 要办成的事 → 行动与时间安排 → 今天的推进 → 结果与经验”理解和处理日常，也允许内容只停留在记录或参考阶段。

底座为各插件提供稳定、流畅的连接，电脑和手机按场景设计布局。本地优先、旧资料兼容、失败不覆盖与用户可控制保持不变；视觉方案继续由用户主导。先把具体流程做顺，再扩展能力，避免强制分类和重复模块。

近期安排见[路线图](../ROADMAP.md)，笔记设计见[笔记流程](随记功能与开发流程.md)，底座参考见[插件化设计](../design/插件化底座与迁移流程.md)。愿景不表示上述能力已全部完成，也不授权立即打包或发布。
