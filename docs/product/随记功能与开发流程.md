# 笔记：功能范围与开发流程

更新：2026-10-23。**N1 与 N2 基础闭环已纳入 Desktop 0.3.0 发布**，包括记录、对象关联和选文确认创建事项；不代表全部后续设想已实现。附件、历史版本和回顾仍属 N3 储备，安排见[后续开发规划](../ROADMAP.md)。案例来源与取舍见[调研](../research/随记与插件架构案例.md)。

## 目的与使用过程

笔记用于捕捉当下的灵感、思考和经验总结。先把想法留下，之后再决定属于哪门课、哪个项目，是否值得采取行动。它补充事情的背景与反思，不把所有文字变成任务。

例如：上完线代写下“矩阵变换可以用图形解释”。N1 先保存和回看原文；N2 再支持关联到“线性代数”对象，预览并确认创建“画三个变换示意图”事项。原笔记保留，完成画图不等于删除笔记或完成整门课程。

## 首个可用版本

| 环节 | 首版行为 | 边界 |
| --- | --- | --- |
| 记一笔 | 应用内任意页面进入轻量记录面板，输入正文即可保存 | 标题、用途和标签均不必填；系统记录创建与修改时间，关联对象待 N2 |
| 保存与退出 | 自动保存草稿，区分正在保存、已保存、失败；失败可重试，保留输入 | 切页/关面板先落草稿；退出未保存时给出保留/重试选择，不能用成功提示代替落盘 |
| 回看 | 按记录日期呈现时间轴，可补记往日，搜索正文/标题/标签，按日期与用途过滤 | 编辑保留 createdAt；显示完整正文，长文有全文入口 |
| 整理 | 见闻、感受、想法、摘录、复盘；用途与标签均可不选，默认未分类 | 不强制先建目录，不自动根据标题合并 |
| 生命周期 | 编辑、归档、移入回收站、恢复与两次确认永久删除 | 已提供对象归属与事项来源引用；正在编辑的记录需先完成或放弃草稿 |
| 数据带走 | 跟随同一个 data 目录、完整 JSON 备份与恢复；单篇/筛选结果 Markdown 导出 | Markdown 方便阅读，完整恢复以版本化 JSON 为准，尚无 Markdown 导入 |

界面模块名为「笔记」，快捷入口与新建按钮为「记一笔」。用途分别表达经历见闻、情绪感受、想法疑问、外部摘录和经验复盘；课程/项目是关联对象，具体主题交给标签，二者不混作用途。默认未分类也是正常记录，不增加待处理义务。当前用途单选，支持不选；多选与自定义尚未实现。归档和回收站放在「更多」，原日期、搜索和标签筛选保留。

旧 daily 显示见闻，reflection/experience 显示复盘；只在显示和筛选时统一，不批量改写原记录或草稿。标题、原文、ID、创建时间、未知字段和原 kind 随完整 JSON 保留；只编辑正文等其他字段不改变旧 kind。文件路径与 journal 服务名沿用，避免破坏数据和工程引用。

编辑面板沿用当前桌面共享弹层、主题、按钮与字号约定；切换保持轻量淡入，尊重减少动态效果。首版为纯文本键入，可按 Markdown 写作并导出，但不解析 HTML 或渲染富文本。侧栏底部「记一笔」和应用内 Ctrl/Cmd+Shift+M 打开，Ctrl/Cmd+Enter 提交。应用关闭状态的全局快捷键、托盘和系统级捕获另行安排。

输入同步保存为草稿，失败保留原输入和光标并显示重试；未能落盘时阻止切页、收起和停用。关闭应用可选择返回保存或明确放弃未保存输入；已落盘草稿正常退出后继续编辑。

## 接到对象和事项（N2 基础已在本地实现）

笔记独立可用。对象插件开启时，可选择主归属并在对象内查看原文摘要、返回笔记；当前在已保存笔记卡片或对象的关联入口选择归属；从课程编辑器直接新建笔记并预填归属仍待后续。沿用现有一来源一主归属，多个相关对象留待关联模型扩展，不暗中改现有规则。

“提炼为事项”先生成可编辑草稿，用户确定名称、日期/截止与归属后再保存。原笔记不变，来源与目标记录保存引用，可以双向返回；重复点击同一次确认不重复生成事项。事项模块关闭时仍能记录，创建入口解释所需模块；对象模块关闭时，原关系保留，显示不可用原因，不假装原记录已删除。

课堂来源先支持课程对象。精确到某次上课布置的作业须跟随 O2 的逻辑课次身份，不根据笔记时间猜是哪节课，也不为此给课程再造一份待办。

## 数据实现与兼容

workspace 外层 schemaVersion 保持 1，增加可选 data.journal 子结构（schemaVersion 1）。实现、字段限制及旧文件兼容见[数据格式](../../desktop/DATA_FORMAT.md#2026-10-21-随记首版)。

| 内容 | 当前字段/职责 |
| --- | --- |
| 原记录 | 稳定 id、可选 title、body、date、kind、tags、revision、createdAt/updatedAt、归档/删除时间、example 标记 |
| 草稿 | draft 保存编辑内容；editId/baseRevision 防止覆盖已变化记录；提交只产生或更新一条原记录 |
| 关系 | objectView.links 支持 journalEntry；actionDrafts 保存提炼草稿与确认后的 task/plan 引用，事项 sourceRef 返回原笔记；完成状态只在原事项 |
| 存储 | 笔记服务使用现有 workspace 适配器，正文与草稿均在同一 data；当前直接过滤查询，不另存索引 |

旧工作区缺 journal 时按空读取，未使用不强制添加。更新保留 ID、创建时间和未知字段；未来子版本拒绝写入，失败不覆盖原文件。普通模式隐藏的示例编辑草稿可暂存于 parkedDrafts，不挤占真实记录草稿。附件与正文历史列为 N3，届时使用 data 内受管理的相对路径和引用清单。

完整备份必须包含关闭模块的数据、草稿和关系；恢复、复制 data、开发者清空的归档范围同步增加。普通模式不能导入或展示虚构笔记，示例既检查按钮也检查服务，不因插件重开自动导入。

## 分阶段开发与验收

| 阶段 | 交付 | 验收后才进入下一步 |
| --- | --- | --- |
| N0：范围与契约（已完成） | 本文、模型、界面状态与记录/任务边界 | 2026-10-20 设计，10-21 增加实现约束 |
| N1：独立笔记（本地实现） | 基于 A1 宿主适配的内置插件；捕获、草稿、时间轴、搜索/标签、归档/回收站、导出 | 保存/重开、写入失败与重试、身份、复制 data、清空归档、示例守卫已验证；待用户体验 |
| N2：对象与行动（本地实现，待体验） | 课程/项目主归属、双向返回、确认提炼事项 | 笔记、对象、事项三个提供者通过契约协作；原文不重复；确认幂等；引用失效、模块关闭、跨记录失败回滚和便携恢复已验证，待用户体验 |
| N3：积累与扩展 | 附件、历史版本、回顾与更多引用 | 单独确认范围，验证容量、附件引用/清理、历史恢复及迁移；AI、云同步均不作为先决条件 |

N1 复用现有 Electron 隔离工作区流程，覆盖中文多行、模拟 composition 事件与光标保持、特殊字符、真实 Markdown 下载、失败重试、页面/退出拦截及停用后清理。浅色/深色和宽窄布局已检查；没有声称物理中文输入法、手机或真实用户资料已全面验收。检查数量及证据见[交接](../HANDOVER.md)。

近期安排：1 当前版体验与小修 → 2 笔记关联课程/项目 → 3 确认提炼事项 → 4 同一事项多段安排 → 5 今天/日历接入。本轮第 2、3 项已实现并分别验证，不把附件或完整知识库并入 N2。与底层和 O2 的统一范围见[路线图](../ROADMAP.md)。每项先代码与验证，再本地体验；获得用户明确确认后才安排封装和发布。
