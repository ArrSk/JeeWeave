# 随记：功能范围与开发流程

更新：2026-10-20。**待开发设计**，本轮没有增加应用入口、笔记库或示例。当前 Desktop 对象视图可关联课程、事项和网页，尚不能保存随记。案例来源与取舍见[调研](../research/随记与插件架构案例.md)。

## 目的与使用过程

随记用于捕捉当下的灵感、思考和经验总结。先把想法留下，之后再决定属于哪门课、哪个项目，是否值得采取行动。它补充事情的背景与反思，不把所有文字变成任务。

例如：上完线代写下“矩阵变换可以用图形解释”；过两天把它关联到“线性代数”对象；需要行动时选中一段，预览并确认创建“画三个变换示意图”事项。原随记保留，事项保存来源引用；完成画图不等于删除笔记或完成整门课程。

## 首个可用版本

| 环节 | 计划行为 | 边界 |
| --- | --- | --- |
| 随手写 | 应用内任意页面进入轻量记录面板，输入正文即可保存 | 标题、分类、标签、对象、时间安排均不必填；系统记录创建与修改时间 |
| 保存与退出 | 自动保存草稿，区分正在保存、已保存、失败；失败可重试，保留输入 | 切页/关面板先落草稿；退出未保存时给出保留/重试选择，不能用成功提示代替落盘 |
| 回看 | 按创建日期呈现时间轴，可搜索正文、按标签与类别过滤 | 编辑不改变创建日期；默认私人本地记录；无标题可用首段生成展示名，不覆盖正文 |
| 整理 | 可选灵感、思考、经验总结、普通记录；可选标签 | 不强制先建目录，不自动根据标题合并 |
| 生命周期 | 编辑、归档、移入回收站、恢复与显式永久删除 | 归档不影响引用；永久删除前说明关联影响，仍保留备份恢复途径 |
| 数据带走 | 跟随同一个 data 目录、完整 JSON 备份与恢复；单篇/选定记录 Markdown 导出 | Markdown 方便阅读，完整关系恢复以版本化 JSON 为准，不能承诺任意 Markdown 导回无损 |

编辑面板沿用当前桌面共享弹层、主题、按钮与字号约定；切换保持轻量淡入，尊重减少动态效果。首版先支持纯文本与轻量 Markdown，不先搭复杂富文本编辑器。应用关闭状态的全局快捷键、托盘和系统级捕获另行安排平台验证。

## 接到对象和事项

随记独立可用。对象插件开启时，可选择主归属并在对象内查看原文摘要、返回随记；从课程进入记录可预填归属，但提交前可以清除。沿用现有一来源一主归属，多个相关对象留待关联模型扩展，不暗中改现有规则。

“提炼为事项”先生成可编辑草稿，用户确定名称、日期/截止与归属后再保存。原随记不变，来源与目标记录保存引用，可以双向返回；重复点击同一次确认不重复生成事项。事项模块关闭时仍能记录，创建入口解释所需模块；对象模块关闭时，原关系保留，显示不可用原因，不假装原记录已删除。

课堂来源先支持课程对象。精确到某次上课布置的作业须跟随 O2 的逻辑课次身份，不根据笔记时间猜是哪节课，也不为此给课程再造一份待办。

## 数据草案与兼容

以下是候选模型，实施前应补验证器、兼容样例与失败测试；**尚未改变 workspace 格式**。

| 内容 | 候选字段/职责 |
| --- | --- |
| 原记录 | 稳定 id、可选 title、body、format、可选 category/tags、createdAt/updatedAt、归档/删除时间、example 标记 |
| 草稿 | 独立 draftId、正文、编辑修订号与最后成功保存状态；发布只转为一条原记录 |
| 关系 | 主归属由对象服务保存；提炼来源使用稳定 RecordRef，不复制对方正文/完成状态 |
| 存储 | 随记命名空间与独立子版本，经宿主仓储写入同一 data；搜索索引为可重建派生物 |

首版优先使用现有 workspace 的可选子结构，由适配器接入；最终字段名与子版本在 A1/N1 开工时冻结。更新保留 ID、创建时间和未知字段；未来版本拒绝不兼容写入，迁移前备份，失败不覆盖原文件。附件与正文历史列为 N3，届时使用 data 内受管理的相对路径和引用清单，禁止把任意外部绝对路径当作可迁移附件。

完整备份必须包含关闭模块的数据、草稿和关系；恢复、复制 data、开发者清空的归档范围同步增加。普通模式不能导入或展示虚构随记，示例既检查按钮也检查服务，不因插件重开自动导入。

## 分阶段开发与验收

| 阶段 | 交付 | 验收后才进入下一步 |
| --- | --- | --- |
| N0：范围与契约 | 本文、模型草案、界面状态与记录/任务边界 | 当前完成设计整理；实现前用隔离夹具验证保存/失败方案 |
| N1：独立随记 | 基于 A1 宿主适配的内置插件；捕获、草稿、时间轴、搜索/标签、归档/回收站、导出 | 离线与重开不丢字，写入失败保留输入；同名不同 ID；备份恢复/复制 data/开发者示例守卫通过 |
| N2：对象与行动 | 课程/项目主归属、双向返回、确认提炼事项 | 随记、对象、事项三个提供者通过契约协作；原文不重复；确认幂等；引用失效、模块关闭和跨记录失败回滚通过 |
| N3：积累与扩展 | 附件、历史版本、回顾与更多引用 | 单独确认范围，验证容量、附件引用/清理、历史恢复及迁移；AI、云同步均不作为先决条件 |

每个实现切片补有意义的领域与契约测试，复用现有 Electron 隔离工作区流程验证真实保存/重开；检查宽窄布局、键盘焦点、中文多行、搜索特殊字符、长内容和失败重试。代码阶段按维护约定运行公共检查和相应 Desktop 回归。本轮只有设计文档检查，没有宣称以上交互已验收。

与底层和 O2 的统一顺序见[路线图](../ROADMAP.md)。每片先代码与验证，再本地体验；获得用户明确确认后才安排封装和发布。
