# 用日常语言理解几微的程序

更新：2026-10-19。说明目前怎样运行，以及对象关联设计会增加什么，不把规划当作已完成。

## 页面与资料在哪里

几微有 Desktop 和 Web 两个客户端。Desktop 是开发重点：本地窗口显示课程表、待办等界面，后台程序管理学校页面、文件与保存。Web 在浏览器运行，有自己的界面和数据库。

桌面 data/workspace.json 是业务主文件；界面报告保存成功前，后台已校验并写入磁盘。浏览器缓存只是兼容副本。升级桌面时复制整个 data，才能一起保留业务、原文与登录状态。两端备份不是同一种格式。

## 多一个事件页面为什么还不够

可以把事情详情做成一个查看入口，但程序要先知道：哪条作业属于哪门课，哪份通知提出了这个要求。否则页面只能把文字摆在一起，修改或删除后仍可能找不到关联。

新设计会给课程/项目稳定编号，让作业、安排和资料保存关系。一个作业在待办和日历里出现，仍是同一份作业；完成后各入口读取它的新状态，不各存一份完成标记。这个能力目前还在设计阶段。

## 各部分的分工

| 部分 | 日常比喻 | 职责 |
| --- | --- | --- |
| 界面 | 工作桌上的窗口 | 展示、收集输入、提供跳转 |
| 业务规则 | 办事约定 | 日期、周次、完成状态；未来的对象关联 |
| 数据服务 | 管资料的管理员 | 查找、一次性保存、处理失败 |
| 平台能力 | 文件柜和设备接口 | 文件、窗口、通知等，各平台不同 |

公共层目前主要服务 Web，Desktop 仍有自己的业务和文件保存流程，不应理解为所有平台已经共用一套完整程序。
