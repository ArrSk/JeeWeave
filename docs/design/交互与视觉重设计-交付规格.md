## 1. 现状诊断（为什么现在的感觉是"普普通通"）

不是主观印象，是可以量出来的。

### 1.1 视觉层的问题

| 位置 | 实测 | 问题 |
| --- | --- | --- |
| 控件描边 `--control-border: #c4c6cc` 对 panel `#fdfdfe` | **1.68:1** | 低于非文本 3:1 门槛，输入框几乎看不出边界；这是"输入框单调"的第一因 |
| 强调描边 `--accent-border: #abbdfd` 对 panel | **1.81:1** | 搜索框、选中态的边框同样糊在背景里 |
| 分隔线 `--line: #dedfe3` 对 panel | **1.31:1** | 分隔线靠"面积感"而非可读性存在 |
| 文本 `#202a3c` 对 panel | 14.17:1 | 正文其实过重，导致层级只能靠字号硬撑 |
| 主题数量 | 17 套（9 旧 + 8 studio） | 全部由"强调/背景/文字"三个种子推导，**同一种材质换颜色**，看起来像同一个界面被染色 |
| 圆角 | 实际散落 **13 种取值**（8/10/12/14px、6/5/4/3/2/9px、50% 圆、0），`--radius: 8px` 只覆盖按钮与字段 | 没有尺度语言：小 chip、卡片、浮层撞在同一个圆角上 |
| 投影 | 仅 6 处，且全是"一片叶子"式单层大模糊（`0 12px 34px` 等 4 种接近的写法） | 没有层级梯度，抬升只能靠加深边框 |

### 1.2 输入控件的问题（用户点名）

现有全部形态只有三种：`input:not([type=file])`、`select`、`textarea`，统一 `min-height:38px`、`border:1px solid var(--control-border)`、`radius:8px`、`focus` 只把边框染成 `--blue`，`focus-visible` 是 `outline:2px solid` 加 3px 偏移。

- 全仓 **129 个 `<label>`、20 个日期框、9 个时间框、10 个数字框、10 个复选框开关**，全部走同一套视觉 → 表单页面读起来像"一堆灰框"。
- 日期/时间直接暴露原生控件：`input[type=date]` 在 Windows 上有自己的日历弹层，与本应用视觉完全无关。
- 星期多选（`desktop-weekday-choices`）是 7 个 checkbox 排一行；插件开关是缩放的原生 checkbox（17px）；都不是能撑起"高级感"的控件。
- `focus` 只有矩形描边，没有过渡、没有底座变化、没有语境提示；**输入这件事本身没有任何"被设计了"的痕迹**。

### 1.3 交互层的问题

- 页面切换只有一次 `opacity .96→1 + translateY(3px)`（`page-motion.mjs`，240ms）。这**不是过渡，是防闪烁**：新旧页面结构瞬间交换，只有新页面淡入，所以视觉上是"闪一下"。
- 查找 = 工具栏里就地展开一个框（原型设计上是对的，见 §2.2 Linear），但展开/收起无动画，结果列表是纯文本按钮堆叠，无选中游标、无分组、无预览。
- 反馈 = 一条 `role=status` 文字 + 6.5s 定时隐藏，没有层级、没有可撤销、没有进场。
- 粒子系统存在，但触发条件是**指针附近持续移动**（`pointermove` + 18px 累计位移 + 单次跳跃 ≤180px 才发射，上限 32 颗，触摸与弹窗打开时不发）。方向是对的，但代价很高：动得越多越亮，**奖励的是"手在动"而不是"事在变"** → 从"氛围"降级为"鼠标装饰"。
- 导航：`prototype.html` 用 `⌂ ◷ ▦ ◇ ✎` 等 Unicode 字符当图标，虽然后来被 `prototype-modules.js` 第 104 行替换成 SVG，但**首帧会闪一次字符**；助手/提醒的关闭按钮直接是 `×` 字符。

### 1.4 结论

现在的界面是"一个完成度很高的原型"：功能都在、结构清楚、可及性底线（标签、键盘、焦点、减少动效）都在，但**没有任何一个地方敢做决定**——没有材质、没有尺度对比、没有签名动作、没有值得记住的一秒。要修的不是"再加点装饰"，而是补上三层缺失：**材质语言、控件语言、动效语言**。

### 2.2 同类产品是怎么做的（一手来源）

**Raycast —「快、简单、令人愉悦」三条原则的落地方式**（[A fresh look and feel](https://www.raycast.com/blog/a-fresh-look-and-feel)）
1. 把**搜索框做大约 40%**：因为"几乎每次交互都经过它"，所以要让它显眼、与结果拉开层级。
2. 把隐藏的 `⌘K` 从一个小按钮搬到**操作栏**：左侧放导航标题与 toast，右侧放当前上下文动作 + 快捷键——让用户**看见**快捷键从而学会它。
3. 图标重做成统一描边宽度与统一圆角的家族（一个描边规则贯穿全套）。
4. **Compact Mode**：为一个具体流程（打开→输入→回车）削掉无关元素。

**Raycast 2.0 技术拆解**（[A Technical Deep Dive](https://www.raycast.com/blog/a-technical-deep-dive-into-the-new-raycast)）
- 让 WebView 应用"不像网页"的具体清单：**不给可点控件加 `cursor:pointer`**（桌面应用不这样）、**多数控件不做 hover 高亮**、设置开独立原生窗口而非模态、popover/tooltip 走原生窗口而非 DOM、**任何视图出现或切换都不得闪**。
- 恰好给了我们"Electron 里怎么装得像桌面原生应用"的正面清单。

**Linear — 命令菜单要贴着发起它的元素**（[Contextual command menu](https://linear.app/changelog/2019-10-07-contextual-command-menu)）
- 原文承认旧做法"不管键盘还是鼠标触发，菜单总在屏幕正中"是不对的；改为"几乎像下拉菜单，但保留可搜索与键盘可控"。

**Things 3 — 交互本身就是产品**（[官方功能页](https://culturedcode.com/things/features/)）
- 打开一条待办时**平滑变成一张白纸**（形态转场，不是淡入）。
- **Magic Plus**：把"新建"按钮拖到目标位置松手即在彼处插入——把"放哪里"这个决定变成一次手势。
- **Quick Find / Type Travel**：不按快捷键，**直接开始打字**就搜索并到达。
- **Jump Start**：一个浮层收拢全部排期决定（今天/今晚/某日/提醒/Someday）+ **自然语言日期**（"tom"、"Sat"、"in four days"）。
- 官方文案强调"每个动画都有目的"、"自定义动画工具包"。

**Notion Calendar — 键盘即主路径**（[官方博客](https://www.notion.com/blog/notion-calendar-helps-you-manage-your-time-more-effectively)）
- `C` 快速建事件、`S` 分享可用时间、`F` 找人约时间；菜单栏常驻显示今天；跨日历**自动阻塞**空闲。

## 3. 设计论点（Direction Contract）

**THESIS（一句话）**
> **"几微"本义是"将要发生之事的细微先兆"。界面应当先把那根几乎看不清的线画出来，再让内容落到线上；用户每一次操作，都是往这面织布上添一根纬线。**

这套语言把产品的三件事连起来：时间（经线，固定不动）、内容（纬线，你添上去）、对象（经纬交汇的那个结）。它不是装饰主题，而是一条能推导出全部视觉决定的规则：

- **线**（1px 发丝线）是唯一的分隔手段 → 取代现状 1.31:1 的灰线堆叠。
- **纸**（暖白纸面 / 墨夜纸面）是唯一的表面材质 → 取代"同一种卡片换颜色"。
- **先兆**：任何新元素进场前，先画出一根发丝线（240ms），内容再落位 → 取代"闪一下"。
- **纬线**：用户操作留下的痕迹（完成、拖拽、输入）才有资格产生动效 → 取代"任何鼠标移动都放粒子"。

**OWN-WORLD**
- 浅色：**澄纸**（`#f1efe9` 纸面 / `#faf9f7` 板面 / 靛 `#3a4a93` 作墨）。暖纸而非冷白，是为了让中文正文在以 13px 为主的工作台上不显薄。
- 深色：**墨夜**（`#101218` 底 / `#1d1f25` 板 / 淡靛 `#9daaee` 作墨）。不是纯黑，保留纸的粉感；强调色提亮到可在深底上直读。
- 材质：纸（哑光、极低投影）+ 发丝线（1px、`--line-strong` 达 3:1）+ 唯一一块"描图纸"（命令面板，半透明+模糊，理由见 §5.4）。
- 字体：中文系统栈（`"Microsoft YaHei UI"` → `"Microsoft YaHei"` → `system-ui`），拉丁与数字走系统 `Segoe UI Variable Text`；**数字一律 `tabular-nums`**；**不使用任何联网字体**。层级靠**字重 + 字号 + 颜色三级**，不靠大写英文 kicker（那是明确禁止的模板痕迹）。

**STORY（一次典型使用怎么走）**
打开 → 扫一眼今天的经线（时间栏）→ 抓住一根纬线（一件事）→ 命令面板把它拉到另一天 → 勾掉它，线被"穿过去" → 提醒自己下次还能这么干。

**FIRST VIEWPORT（第一屏必须证明的三件事）**
1. 这是**围绕时间和事情**的界面，不是"功能图标仓库"：今天页首屏就同时出现时间结构与事情上下文。
2. 状态一眼可辨：进行中 / 待办 / 已完成 / 已逾期，用形状与描边区分，不只靠颜色。
3. 全局只有**一个**搜索入口、**一个**新建入口、**一个**助手入口（现状已如此，保留），且三者都在命令面板里可达。

**RISK（我会承担的风险）**
暖纸底在 900px 高度的密集课表里可能显脏 → 对策：课表单元格用 `--elev`（纯白/纯深层）承托，纸色只做外框与间隔；深色主题下 `--line` 故意做到 1.31:1 的"看不见"，靠 `--line-strong` 只在需要区分的地方出现。
不做大面积模糊、不做渐变文字、不做彩色左边框、不做同尺寸卡片阵、不做滚动劫持——这些是"模板感"的来源，一律禁止（与 Impeccable craft-floor 的禁令一致）。

## 4. 设计原则（Codex 遇到本文没写的细节时的裁决顺序）

1. **先有线，再有色。** 任何分隔优先用 1px `--line`；只有在必须被"看见"的结构边界才升到 `--line-strong`。禁止彩色 >1px 的左侧/右侧装饰条。
2. **一个页面一个主动作。** 每屏最多 1 个 `primary` 按钮 + 最多 1 个签名动效（技能数据：每屏 ≤2 个活跃动画元素）。
3. **写下来的东西优先。** 标签永远可见，不用浮动标签（中文双行标签在 40px 高度里必然撞字）；placeholder 只做示例，绝不承担标签职责。
4. **动效只奖励真实操作。** 指针飘过不产生粒子；只有"完成、拖拽落位、面板展开"这三类有结果的动作才发射。
5. **退出快于进入 30%。** 任何过渡，退出时长 = 进入 × 0.7。
6. **不明则不作。** 本文没规定的状态，一律回落到最近的同类组件规范，不新造第三种样式。

### 5.3 间距、圆角、层级

- 间距基数 **4**：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 56`。组件内 `8–12`，区块间 `24`，页面级 `32–40`。**标题上方间距必须大于下方**（`24` 上 / `12` 下）。

| 层 | 用法 | 值 |
| --- | --- | --- |

### 5.4 材质：为什么只有一处是玻璃

技能原文指出玻璃依赖"下面有鲜艳背景"。本应用唯一符合条件的时刻是**命令面板覆盖在真实内容之上**——它下面是自己的课表/日历。因此把命令面板定义为**描图纸（tracing paper）**：`background: color-mix(in oklab, var(--elev) 76%, transparent)` + `backdrop-filter: blur(18px) saturate(1.15)` + `1px solid var(--line-strong-soft)`，并有 `@supports not (backdrop-filter: blur(1px))` 回退到不透明 `--elev`。**其他任何表面一律不许用 `backdrop-filter`**（同时最多 1 层，保证 GPU 预算）。

### 5.6 推导算法（直接替换 `appearanceTokens()` 的核心）

```js
// 逐项实现；常数不得改动。sRGB → 线性亮度，WCAG 2.x 对比度。
const luminance = (hex) => { /* 现有实现保留 */ };
const contrastRatio = (a, b) => { /* 现有实现保留 */ };
const mix = (a, b, w) => { /* 现有实现保留 */ };

// 只沿"变深/变浅"一个方向求解，取满足全部背景的最小位移，保留原色相。
function solve(base, backgrounds, ratio) {
  let best = null;
  for (const pole of ['#000000', '#ffffff']) {
    for (let i = 0; i <= 200; i++) {
      const candidate = mix(base, pole, i / 200);
      if (backgrounds.every(bg => contrastRatio(candidate, bg) >= ratio)) {
        if (!best || i < best.i) best = { i, candidate };
        break;               // 该方向的最小位移
      }
    }
  }
  return best ? best.candidate
    : ['#000000', '#ffffff'].reduce((a, b) =>
        minRatio(b, backgrounds) > minRatio(a, backgrounds) ? b : a);
}

export function appearanceTokens(value) {
  const { colors } = normalizeAppearance(value);
  const dark = luminance(colors.text) > luminance(colors.background);
  const canvas = colors.background;

  const panel  = mix(canvas, '#ffffff', dark ? .055 : .62);
  const elev   = dark ? mix(canvas, '#ffffff', .10) : '#ffffff';
  const sunken = mix(panel, colors.text, dark ? .055 : .06);
  const bgs    = [panel, canvas, elev, sunken];

  const line       = mix(panel, colors.text, dark ? .10 : .14);        // 装饰线，允许 1.3:1
  const lineStrong = solve(mix(panel, colors.text, dark ? .50 : .55), [panel, canvas, elev], 3.0);
  const lineSoft   = mix(panel, colors.text, dark ? .16 : .20);       // 极弱内描边

  const ink1 = solve(colors.text,            bgs, 7.0);
  const ink2 = solve(mix(colors.text, panel, .24), bgs, 5.5);
  const ink3 = solve(mix(colors.text, panel, .44), bgs, 4.6);

  let accentSoft = mix(panel, colors.accent, dark ? .14 : .08);
  let accent     = solve(colors.accent, [...bgs, accentSoft], 4.8);
  accentSoft     = mix(panel, accent, dark ? .14 : .08);
  accent         = solve(accent, [...bgs, accentSoft], 4.8);

  const onAccent = solve(dark ? canvas : '#ffffff', [accent], 4.6);
  const status = (seed) => solve(dark ? seed.d : seed.l, bgs, 4.5);
  // ok: 浅 #1b9466 / 深 #3fbb87；bad: 浅 #c13041 / 深 #f28c94；warn: 浅 #b07d18 / 深 #e0b06a

  return { /* 按 §5.7 的键名输出 */ };
}
```

**关键改变 3 处**（这是"高级感"的技术根因）：
1. `--control-border` **不再是"面板与文字混 26%"**，改为 `--line-strong`（强制 ≥3:1）——输入框终于有边界。
2. `--muted` 拆成 `--ink-2`（≥5.5，次级信息）与 `--ink-3`（≥4.6，辅助信息），不再让 12px 文字挤在 4.2 边缘。
3. 强调色在 `accentSoft` 上**二次求解**，保证 `--accent` 在"浅底强调块"上也 ≥4.8（现状 `#315efb on #f0f3fe` 只有 4.60，勉强）。

## 7. 输入系统（用户点名的重点）

一句话：**把"框"变成"有底座的刻度"**。三层结构 —— 标签（刻度）+ 底座（承托）+ 线头（激活指示）。

### 7.1 字段 Anatomy

```
 截止日期              ← label：11/16, 500, --ink-3, margin-bottom 6px
┌───────────────────┐  ← field：height 40（紧凑 34）, radius 10px,
│ ▌ 2026-10-31   ⌄ │     background --elev, border 1px --line-strong
└───────────────────┘     ↑ 左侧 2px "线头"：见 §7.2
   周五 20:00 截止        ← help：12/18 --ink-3, margin-top 6px（可选）
```

### 7.2 状态机（**这是"输入框不单调"的核心**）

| 状态 | 底座 | 描边 | 线头（左 2px） | 其他 |
| --- | --- | --- | --- | --- |
| rest | `--elev` | 1px `--line-strong` | 透明，`scaleY(0)` | `--ink-1` 文本；`--ink-3` placeholder |
| hover | `--elev` | 1px `--line-strong` 加深一档 | 透明 | 90ms 内完成，不动位移 |
| focus | `--elev` | 1px `--accent` + 外圈 `0 0 0 3px var(--focus-halo)` | **`--accent`，`scaleY` 0→1，160ms，`--ease-out`** | caret `--accent`；标签同步升为 `--ink-2` |
| typing | 同 focus | 同 focus | 保持 | 底座**不做**弹跳；只有 label 的"字数比例"出现 |
| invalid | `--elev` | 1px `--bad` + 外圈 `0 0 0 3px color-mix(bad 14%)` | `--bad` | 错误文案就地显示，`aria-describedby` 指向它；字段右下角 `!` 图标 |
| disabled | `--sunken` | 1px `--line` | 透明 | 文本 `--ink-3`；`cursor:not-allowed`；不出现在 Tab 顺序 |
| readonly | `--sunken` | 1px 虚线 `--line-strong` | 透明 | 可选中复制，不可编辑 |

**线头（weft tick）实现要点**：用 `::before`，`position:absolute; left:-1px; top:50%; width:2px; height:calc(100% - 12px); border-radius:2px; background:currentColor; transform:translateY(-50%) scaleY(0); transform-origin:center; transition:transform var(--dur-2) var(--ease-out)`；`:focus-within` 时 `scaleY(1)`。**只动 transform，不触发重排。**
`prefers-reduced-motion` 下：`transition:none`，直接 `scaleY(1)`（保留状态可辨，取消运动）。

### 7.3 六类专用控件（每一类都要有专属外观与键盘路径）

**(1) 日期 —— `date-field`**
- 视觉：`40px` 底座，右侧 `calendar` 图标；值用 `--text-num` + `tabular-nums`；今天用 `--accent` 小圆点标记在图标右上。
- 弹层：`popover`（不是 `dialog`），宽 `286px`，7列网格；今天 `--accent` 实心圆；选中 `--accent-soft` 底 + 1px `--accent` 描边；跨月日期 `--ink-3`；底部两枚快捷 chip："今天 / 明天 / 本周五"。
- 键盘：`Enter` 展开 → 方向键移动日 → `Enter` 选定 → `Esc` 关闭并回焦。`Tab` 不进入网格内部（用方向键，避免 42 个 Tab 停点）。
- **保留原生 `<input type=date>` 作为数据源与无障碍兜底**：自定义弹层只负责显示与选择，选中后写回原 input 并派发 `input`/`change` 事件（否则现有表单读取 `form.elements.date.value` 的逻辑会全崩）。这是硬约束。

**(2) 时间 —— `time-field`**
- 视觉：底座内**两个窄列**（时/分）用 `--text-num`，中间一个 `:`；右下角 `clock` 图标。
- 输入：直接键入 `0930` → 自动成 `09:30`；键入 `9` + `p` → `21:00`（本地解析规则，**只回填输入框，不进入业务层**）。上下方向键 ±15 分钟（`Shift` ±60）。
- 弹层：小时/分钟双滚轮，`Enter` 确认。同样写回原生 input。

**(3) 数字（节次、金额、次数）—— `number-field`**
- 视觉：右侧垂直步进器（上/下两个 16px 热区，命中区 24×24），值 `tabular-nums`、右对齐；超限时底座 `--bad`。
- 键盘：`↑/↓` ±1，`Shift+↑/↓` ±10，`PageUp/PageDown` ±步长×10。

**(4) 星期多选 —— `weekday-set`**（替换现状 7 个 checkbox）
- 视觉：`role="group"` 的 7 个等宽 chip（`min-width 38`, `h 32`, `radius 8`）；选中态 `--accent` 填充 + `--on-accent` 字 + `aria-pressed="true"`；未选 `--elev` 底 + `--line-strong` 描边；"全选/单选提示"下方 `--ink-3` 一行小字说明当前选了几项。
- 键盘：`Tab` 进组 → `←/→` 移动 → `Space` 切换；**读屏可感知**：每个 chip 是 `role=button` + `aria-pressed`，组上 `aria-label="每周重复的星期"`。

**(5) 标签输入 —— `tag-field`**
- 视觉：底座会随 chip 换行增高（`min-height 40`，最大 3 行后内部滚动）；chip `h 24`、`radius 6`、`--sunken` 底、1px `--line-strong`、右侧 14px 删除图标（命中区 24）。
- 键盘：`Enter`/`,`/空格 提交；空输入时 `Backspace` 删除最后一个 chip；`←` 从空输入进入 chip 区，`Delete` 删除；每个 chip 有 `aria-label="移除标签 X"`。
- 输入法：`compositionstart` 期间不提交（现状搜索已处理，这里同理）。

**(6) 开关 —— `switch`**（替换现状 17px checkbox）
- 视觉：轨道 `44×24`，`radius 12`；拇指 `18px` 圆，左 3px 起；`on` 时轨道 `--accent`、拇指移到右，`140ms cubic-bezier(.2,.7,.2,1)`；`off` 时轨道 `--sunken` + 1px `--line-strong`。焦点：外圈 `--focus-halo`。
- **保留原生 `<input type=checkbox role=switch>`**，用 `appearance:none` + 伪元素画，不替换元素本身（模块开关的现有事件监听、`indeterminate` 部分开启态必须继续工作；`indeterminate` 用轨道内一根 1px 横线表示，语义靠 `aria-checked`）。

**（补充）文本域 —— `textarea-field`**
- `field-sizing: content`（Chromium 123+，本机 152 可用），`min-height 72`、最大 12 行后滚动；右下角显示"字符比例"（仅当 `maxlength` 存在且 >25% 时出现，`--ink-3`）；超限时底线 `--bad` 且不阻止输入（与现状一致）。

**（补充）下拉 —— `select-field`**
- **保留原生 `<select>`**，只做 `appearance: none` + 右侧内联 SVG 箭头 + 与字段一致的底座/状态。理由：原生下拉的键盘、输入法、无障碍由平台保证，自绘 popover 在 129 个表单点位上风险远大于收益。选中值用 `--ink-1`，占位项用 `--ink-3`。

### 7.4 表单级规则

- 必填：标签右侧 `*`，颜色 `--bad`，`aria-required="true"`。
- 校验时机：**失焦校验 + 提交时聚焦首个错误**（技能数据：不要每次输入都校验）。错误摘要仅用于 ≥6 字段的表单，置于顶部 `role="alert"` + `tabindex="-1"`，逐条链接到字段。
- 破坏性操作（删除、清空、放弃草稿）：`danger` 视觉 + 二次确认，且确认按钮**不作默认焦点**。
- 长表单（事项编辑 20+ 字段）：按"是什么 / 什么时候 / 为什么 / 关联"四组分区，每组一道 `--line` 分隔 + 11px 组标题；默认收起低频组（目标、完成标准、所属对象）。
- 提交反馈：按钮进入 `aria-busy` + 文字替换为"保存中…" + 内联 spinner（现有 `button[aria-busy]::before` 保留并统一到 `--accent`），成功 → 就地 `--ok` 一行 + 按钮回位；失败 → 就地错误行，**保留全部输入**（现状已如此，必须保持）。

## 9. 动效系统

### 9.1 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `--dur-1` | `90ms` | hover、颜色、透明度 |
| `--dur-2` | `160ms` | 字段/开关/线头、焦点 |
| `--dur-3` | `240ms` | 面板、浮层、列表项进退 |
| `--dur-4` | `380ms` | 页面切换、签名动作前段 |
| `--dur-5` | `620ms` | 完成勾选的"穿线" |
| `--ease-out` | `cubic-bezier(.16,1,.3,1)` | 进入（主缓动） |
| `--ease-inout` | `cubic-bezier(.2,.7,.2,1)` | 双端（位移类） |
| `--ease-snap` | `cubic-bezier(.34,1.56,.64,1)` | 仅小元件（≤8px 位移、≤40% 缩放），禁止用于大面板 |

**禁止**：`linear` 以外的"匀速长过渡"、`ease-in-out` 默认值、`bounce` 系列用于大面积、任何只改变 `width/height/top/left` 的过渡（必须换 `transform`/`clip-path`/`grid-template`）。

### 9.2 五个签名动作（这是"炫酷高级"的全部落点，不得增加第六个）

**① 先兆线（Omen）——所有内容进场的统一语法**
面板/区块首次出现时，边界处先画出一根 1px `--line-strong` 的线（`scaleX` 0→1，`240ms`，`--ease-out`，从左侧起），线到位后内容 `opacity 0→1 + translateY(4px→0)`（`200ms`）。总时长 ≤ 440ms，**每次只允许一个区块画线**（页面级只画一次，不给每个卡片都画）。

**② 穿线（Weave-through）——完成勾选**
点击完成时：勾选框内的对勾分两笔画出（`stroke-dashoffset`，共 `380ms`，`--ease-out`），同时一条 1px `--ok` 横线从文字左端延伸到右端（`620ms`，`--ease-inout`），文字在 `380ms` 后降到 `--ink-3` 并**不下沉**（不位移，避免整行跳动）。
条目**留在原位 5 秒**，期间底部出现 1px 进度线（宽度 100%→0，`5s linear`，颜色 `--line-strong`）+ 右侧"撤销"按钮；5 秒后条目淡出并移入已完成分组（`--dur-3`）。
`reduced-motion`：不画线、不描边，立即置为完成态，撤销仍保留 5 秒。

**③ 拖拽纸条（Paper lift）——安排时间 / 移动到日历**
拿起时：`scale 1.02`、`rotate 1.5deg`、阴影升到 `--elev-3`、原位置留下 `--sunken` 占位条（`240ms`）。拖动中跟手用 `transform`，**每帧只写 transform**（`requestAnimationFrame` 合并）。
落点吸附：时间网格高亮为 `--accent-soft` 色带 + 顶部 1px `--accent`，色带高度对齐 15/30 分钟吸附格；松手时纸条 `rotate→0 + scale→1`（`320ms`，`--ease-out`），落位后发射 ≤8 颗"织尘"（见 ④）。
**键盘等价**（必须实现，技能明令拖拽要有按钮/键盘替代）：聚焦条目按 `Ctrl+↑/↓` 调整日期、`Alt+↑/↓` 调整 30 分钟、`Enter` 提交，行为与拖拽完全一致。

**④ 织尘（Weft dust）——只在这三个时刻发射**
仅：命令面板打开、拖拽落位、完成勾选。每处 ≤24 颗、寿命 ≤900ms、半径 1–2px、颜色 `--accent` 36% 不透明度、初速向下漂 0.35px/帧并衰减；DPR 上限 2；页面 `hidden` 或失焦 500ms 后**停止 rAF**；`prefers-reduced-motion: reduce` 时**整个画布不创建**。
**移除现状的"任意指针移动即发射"**——这是把廉价动效换成稀缺动效的关键一步。

**⑤ 命令面板（Command Weave）**
`Ctrl+K` 时：当前工作区做 `filter: saturate(.7)` + `opacity .55`（`160ms`）；面板从工具条下方 **`translateY(-8px) → 0` + `scaleY(1)` 由顶部起**（`320ms`，`--ease-out`），背景是描图纸（§5.4）；结果列表首项有 1px `--accent` 游标条，方向键移动时游标 `translateY` 以 `180ms --ease-out` 跟随（只动 `transform`）；输入为空时按"最近 / 今天 / 对象"分组，无结果时展示"试试：`课程`、`作业`、`10月`"建议 chip 与"清除筛选"动作（技能：无结果必须给建议）。
`Esc` 先清空再关闭；关闭后焦点回到发起按钮。

### 9.3 页面切换（替换现状的"闪一下"）

- 预创建目标页 → 目标页 `opacity 0→1` + `translateY(6px→0)`（`380ms`，`--ease-out`）；源页 `opacity 1→0` + `translateY(0→-3px)`（`180ms`，`--ease-inout`）——**退出 180 vs 进入 380，符合"退出快于进入"**。
- 源页在过渡期间 `inert` + `aria-hidden="true"`，目标页立即可操作（逻辑导航不等动画）。
- 导航指示条（选中项下 2px）以 `spring` 跟随：`transform:translateY()` + `scaleX()`，`--dur-3`，`--ease-snap`（位移小，允许轻微回弹）。
- 快速连按切页：`active?.cancel()` 后立刻起新动画（保留现有 `createPageMotion` 的可中断思路，但换成上面这套时间参数）。

### 9.4 浮层与弹窗

- 详情/编辑浮层：右侧滑入 `translateX(12px→0)` + `opacity`（`--dur-3`），退出 `180ms`；背景遮罩 `color-mix(--canvas 62%, transparent)`（**不是纯黑**），点击遮罩关闭但 `Esc` 优先。
- 遮罩必须让被遮内容"退后"：`scale(.994)` + `saturate(.8)`，`240ms`。禁止整屏模糊。
- 浮层内第一个输入自动获焦；关闭时回焦到发起控件（现状已有 `returnFocus`，必须保留）。

### 9.5 减少动态效果（硬门槛）

`@media (prefers-reduced-motion: reduce)`：
- 所有时长 ≤ `90ms`，**所有位移动画归零**（`translate`/`scale`/`rotate` 一律不执行），保留 `opacity` 与颜色变化作为状态提示。
- 粒子画布不创建（`#desktop-design-particles { display:none }`）。
- 线头直接 `scaleY(1)`；穿线直接跳到完成态；拖拽改用"按键移动 + 立即落位"。

### 9.6 性能约束

- 每屏并发动画 ≤ 2；同时存在的 `backdrop-filter` ≤ 1 层。
- 动画只允许 `transform` / `opacity` / `filter` / `clip-path`；**任何动画期间不得改变布局属性**。
- 列表进场错峰 ≤ 0.03s/项，且总时长 ≤ 500ms（技能数据）。
- `will-change` 只在拖拽与命令面板打开期间临时挂，结束即摘除。
- 不使用 `animation-timeline: view()` 做滚动驱动动画（桌面应用易被判为抖动，且 reduce 回退复杂）。

## 12. 工程约束（Codex 必读，违反即返工）

1. **无构建、无新依赖。** 不引入 React/Vue/Tailwind/GSAP/字体包/图标库。只用 `desktop/*.mjs` + `desktop/*.css` + 原生 DOM。
2. **入口文件名不变**：`workbench.css`、`desktop-design.css`、`prototype-modules.js`、`prototype.html` 保持原名（`package.json` 的 `build.files` 白名单、`mobile/prepare.mjs` 的资源替换、多个测试的选择器都依赖它们）。
3. **新增文件必须同步**：加进 `package.json` 的 `build.files`；若需手机预览，同时确认 `mobile/prepare.mjs` 的 `\.(mjs|js|css|svg|png)` 过滤能覆盖。
4. **不得改动业务与存储**：不改 IPC 通道、命令名、`workspace.json` 格式、插件生命周期、写盘失败回滚路径。UI 层只负责"显示"与"派发意图"。
5. **必须保留的锚点（测试与用户肌肉记忆依赖，勿重命名/勿删除）**：`#desktop-search-open`、`#desktop-search-input`、`desktop-search-panel`、`desktop-search-result`、`[data-search-open]`、`[data-view]`、`#desktop-assistant-open`、`#desktop-layout-menu`、`#desktop-bar-handle`、`#desktop-bar-reset`、`#desktop-module-*`、`[data-module]`、`#desktop-add-course`、`#desktop-load-demo`、`#desktop-developer-mode`、`data-workspace-layout`、`data-layout`、`data-palette`、`.nav .desktop-nav-label`、`kbd`（外观壳测试依赖其隐藏态）。
6. **主题令牌只能出现在两处**：`workbench.css` 的 `:root` 默认值 + `appearance.mjs` 的 `appearanceTokens()` 输出。组件 CSS **禁止硬编码十六进制色值**（`#fff` 白名单除外，且必须用 `--elev` 替代）。
7. **保留下拉/浮层的行为契约**：`course-overlay.mjs` 的 `show/close` + `returnFocus` + `fitViewport`；`search-ui.mjs` 的 IME/`Esc`/草稿保护/外点收起。视觉可换，行为不可换。
8. **Electron 安全设置不变**：`contextIsolation`、`sandbox`、无 `nodeIntegration`；所有新 DOM 必须走现有 `escapeHtml`（`ui-text.mjs`），**禁止字符串拼接未转义的用户数据**。
9. **每个 CSS 文件顶部写一行归属注释**，说明它负责哪一层（tokens / inputs / chrome / motion / pages），避免出现第四个"什么都往里塞"的样式文件。

**建议新增文件（保持职责单一）**

| 文件 | 职责 |

| `desktop/design-inputs.css` | 只放 §7 的字段/六类控件/开关/chip |
