# 插件化底座：接口定义与渐进迁移

更新：2026-10-21。**现有 Desktop 内置业务已统一迁移；跨端、第三方及新产品功能仍为设计**。受用户提出的 DeepSeek Harness“万物皆插件”启发，来源见[案例调研](../research/随记与插件架构案例.md)。首片使用仓库内轻量宿主，未安装 Cordis，未改变现有技术栈和真实资料。

## 迁移历史与当前范围

- workbench-host.mjs 提供带版本的服务、命令、页面导航、事件及按 owner 管理的 scope。服务调用检查启用状态，停用后旧代理失效；资源逆序释放，旧页面 leave 失败则不进入下一页。
- prototype-modules.js 作为组合入口，桥接 workspace/对象接口、注册事项服务，将既有导航接入宿主。各旧编辑器继续工作，并未全部迁移为独立插件。
- journal-feature.mjs 按随记开关激活领域服务、捕获命令、界面和监听。停用前先保存草稿；失败不变更偏好，成功后撤销服务/命令/监听/弹窗，保留数据。事件观察者异常不冒充已提交写入失败。
- workspace-transaction.mjs 提取已有原子写入入口，旧 workbench-data 导出兼容；随记存储复用 workspace/preload，不另建数据库。统一主题变量、820px 弹层和轻量切换继续由现有壳提供。
- 2026-10-21 第二片只迁移事项编辑器：item-service.mjs 提供 list/get/context/save/toggle/setPhase/remove，界面不再读写业务存储或导入对象实现。对象通过窄接口准备既有归属变化，事项服务用原工作区事务一次提交；这仍是旧格式适配，不是通用跨插件事务协议。
- 第三片仅迁移日历对事项的查询、详情、完成与阶段进度，复用同一 items v1；日历不再读写事项私有键。日历偏好和课程投影保持现有实现；它是服务消费者接入，尚不是日历完整生命周期迁移。
- 第四片只迁移今天页的事项查询：items v1 增加向后兼容的只读 onDate(date)，统一原日期/完成筛选和开关/示例守卫，不保存派生副本。今天页的课程投影、界面和定时刷新沿用原实现。
- 第五片只迁移总览事项计数：items v1 增加只读 summary()，统一可见/启用记录的总数、未完成和已完成统计。沿用原记录完成口径，未来事项计入，单次重复完成不代表结束整个重复；关闭全部来源时不调用。
- 第六片只迁移网页记录/草稿数据边界：web-captures v1 提供查询/保存/确认，页面和总览经服务读取，旧导出转发保留，开关/示例守卫覆盖兼容入口。确认仍复用原 tasks/captures 两键事务；通过 items 提供者创建来源事项、通用跨提供者事务及完整网页生命周期尚未迁移。网络抓取、界面与格式不变。
- 第七片补网页到事项接口：items v1 增加 addFromSource，网页经宿主调用并同步准备自身草稿变化，由事项服务一次提交两方数据。校验、来源去重、ID 冲突和事项写入归提供者，网页不再接触 tasks 私有键。准备失败/异步/覆盖事项集合均拒绝，缺失或不兼容服务不回退直写；旧确认签名由组合层适配。该机制只支持可信内置代码、单工作区内无写入/无异步的准备，不替代完整依赖图、事务协调器或外部隔离。

- 第八片只迁移对象聚合中的事项/网页来源：候选通过 list、详情和提交关联/打开来源前通过 inspect 校验。可见来源返回快照，隐藏只返回状态；关闭或不可用时保留引用而不显示正文，服务失效不误报删除、不回退私有键。课程适配、对象自身编辑和通用引用协议仍待后续迁移。

- 第九片只补对象的课程来源读取：courses v1 提供只读 listEntries/inspect，保留课表范围、未排课、作息与调整。查询不初始化数据或变更选择；返回的上下文也过滤隐藏示例。对象聚合不再读取任何来源业务存储键，课程编辑/导入和其他课程消费者仍待后续迁移。

- 第十片只迁移今天页课程查询：courses.onDate(date,time) 复用原课次状态规则，只读选择可见当前表，不保存今天副本；可见投影也过滤隐藏课程的调整。服务失败保留事项并提示，调整按钮重查课表范围/课程/原日期；日历、总览课程读取与课程编辑/导入继续后续迁移。

以上为此前逐步迁移的历史。用户随后要求全部改造，当前已补齐现有内置业务的数据读写、依赖/版本、命令/引用路由、命名空间及启停资源管理。实际契约以[内置插件接口](../development/内置插件接口.md)为准，早期目标中跨端、第三方和 N2 等部分仍未实现。

## 当前缺口

Desktop 的 modules.mjs 保留用户功能开关，plugin-runtime 负责运行清单、依赖和生命周期；业务数据操作均经提供者，prototype-modules.js 保留原界面渲染与装配。当前仅运行可信内置代码，第三方包发现/加载、隔离与跨端适配不在本轮。N2/O2 是尚未开发的新业务，不能把内置底座完成等同于它们已完成。

## 底座与业务的目标职责

| 层 | 应承担 | 应通过别的提供者获得 |
| --- | --- | --- |
| 最小宿主 | 启动/退出、窗口与应用壳、装载和生命周期、依赖/版本校验、接口路由、权限、事务/迁移/备份机制、诊断 | 具体课程、事项、笔记和费用规则 |
| 平台适配服务 | 受限文件/通知/窗口/登录能力；Desktop 与 Web 各有实现 | 页面业务，不向业务暴露任意 Node/文件系统 |
| 业务插件 | 对象、事项、课程、随记、网页采集与导入各自提供领域服务、校验与视图 | 经宿主取得其他领域服务，不读其他插件私有文件或导入其页面实现 |
| 聚合插件 | 日历、今天、对象详情读取各提供者的投影 | 不另存完成状态、课程副本或笔记正文 |

宿主提供命名空间持久化与跨命名空间事务，领域记录结构和业务校验归其业务提供者。通用引用解析由宿主注册表路由，课程归属等语义仍属于对象/课程服务。主题变量、共享弹层与 UI 插槽统一由壳提供；各视图可插拔，用户仍只维护一份主题和同一个 data。

纯日期/周次函数继续留在 core，纯函数复用不必绕一遍消息。共享契约应与 React/DOM/Electron 解耦，具体目录待 A0 依赖审计确定，不能直接把现有 React FeatureModule 宣称为平台无关协议。Web 后续可实现同一协议的适配器，本轮不改变它的技术栈或数据格式。

## 契约应先定义什么

以下名字仅用于说明角色，不是已发布 SDK/API。

| 契约 | 需要表达的内容 |
| --- | --- |
| 插件清单 | 稳定 id、插件版本、兼容 hostApiVersion、平台入口、必需/可选服务及版本、能力申请、UI 贡献、数据子版本 |
| 服务定义 | 名称/版本、输入输出与校验、错误、可用性、取消/超时、是否只读、事务与幂等约束；分别编写提供者和消费者测试 |
| 查询 | 读取快照/投影，带 revision；明确缺失、禁用、已删除及不兼容，不能把失败冒充空集合 |
| 命令 | 创建/修改/关联/跳转等有明确结果的操作；跨业务写入通过受控用例与事务，权限校验在执行边界生效 |
| 事件 | 提交后的事实通知，包含来源、revision、correlationId 与受限引用；消费者失联后可重读快照，不依赖事件维持唯一数据 |
| UI 与资源 | 导航、详情贡献、按钮/快捷操作、弹层以及注册返回的 disposer；统一焦点与滚动恢复，禁止跨插件查 DOM 再模拟点击 |

直接请求结果走服务/命令，提交后的变化再通知订阅者。不要把所有请求、正文和写库行为都丢入全局事件总线：这会掩盖失败和执行顺序。事件不默认广播笔记全文、账号、Cookie 或抓取原文；去重、来源追踪和修订号避免“你更新我、我更新你”的循环。重试写操作使用幂等键；事件允许重复，消费者应可去重/重读，不能承诺跨崩溃恰好一次。

引用优先兼容现有 `{ collection, id, containerId? }`，保留 tasks/plans 身份与课程的课表范围。提供者注册解析/摘要/打开接口，后续新增 owner/schema 信息用映射适配，不批量重编号。记录不存在与提供者关闭要分别呈现；对象中保留失效引用和解除入口，不自动找同名替代。

## 一次跨插件操作（N2 目标，尚未实现）

以“随记提炼成事项并归到课程对象”为第一条互通用例：

1. 随记提供者生成草稿，用户核对内容、期限与归属。
2. 宿主检查事项与对象服务版本、能力、记录修订；全部需要的参与者可用才继续。
3. 事项提供者校验，随记提供者确认来源，对象提供者校验归属；宿主将写事项、来源与关系放入同一受控事务。
4. 成功后返回原引用与新引用，发布已提交事件；失败则全部不写，保留草稿和原文。重复确认返回同一次结果。
5. 日历、今天和对象详情各自重读投影，不接收一份可自行修改的笔记/事项副本。

首阶段仅对现有单一工作区事务内的提供者保证原子性，事务中不等待外部网络或任意插件钩子。将来接外部服务时需另设待处理/补偿流程，不能将网络请求包装成已经具备的分布式事务。

## 激活、禁用和故障

宿主先检查清单、版本与依赖图，循环依赖拒绝激活；必需依赖缺失说明原因，可选依赖缺失则降级。随记不应强依赖对象/事项，否则用户关闭其他功能就无法记录。

生命周期按注册元信息 → 满足依赖后激活 → 停止接新操作 → 保存草稿/等待或取消有界在途操作 → 释放注册与资源执行。页面、命令、监听、计时器、观察器和平台句柄都登记到所属生命周期；卸载后无幽灵按钮、残留课表或后台重复任务。必需依赖被关闭时，消费者先停止或转为明确的只读不可用态；不删除业务资料。

禁用与卸载默认保留命名空间。完整备份、搬迁、恢复和开发者清空归档覆盖已关闭/未知插件数据及附件；索引可重建，正文不可擅自清除。迁移要有旧版本夹具、备份、事务与回滚，遇到未来版本拒绝破坏性写入。原有 0.1/0.2 兼容路径在替换前后都要验收。

## 权限与隔离

第一阶段仅运行仓库维护的可信内置插件，同进程故障仍可能影响页面，能力清单与资源释放不等于安全隔离。登录会话/Cookie、任意文件、网络和全局数据重置是受限能力；权限在主进程/提供者检查，不能仅靠隐藏按钮或清单声明。

第三方代码执行留到 A3：先确定独立执行环境、受限可序列化桥接、超时/崩溃处理、包来源和兼容升级策略，再开放安装。受限插件 UI 不获得宿主 DOM/Node 权限。外部插件开发套件、市场、脚本热更新均不属于第一阶段交付。

## 原开发切片与验收（历史计划）

| 切片 | 工作 | 通过条件 |
| --- | --- | --- |
| A0：依赖与契约 | 列出现有调用/私有键/写入路径；冻结最小服务、引用、事务、生命周期；比较轻量宿主与 Cordis | 有依赖图、接口样例、失败矩阵与选型依据；仍可运行原界面，不迁真实数据 |
| A1：薄宿主与桥接（首片本地实现） | 已接 workspace、只读对象/事项服务、统一页面路由及随记生命周期；其余契约继续补齐 | 本片原 ID/备份/开关兼容、服务错配/失效与资源清理已测；不代表全部业务已迁移 |
| N1/N2：随记闭环 | 随记通过宿主保存，随后与对象、事项互通 | 独立记录可用，跨三个提供者完成上述用例；本地体验验证后再迁更多模块 |
| A2：内置业务迁移（本地完成） | 当前现有业务均经服务、路由、命名空间和生命周期 | 兼容/失败/启停/导入/搬迁/恢复回归通过；新功能与第三方另验收 |
| A3：外部扩展 | 隔离、权限、SDK 兼容与安装/升级；需另定范围 | 故障隔离/越权拒绝/卸载清理/旧数据恢复全部验收后才提供安装入口 |

A0 要记录启动、切页、保存与退出的现有基线，再比较实验开销；不预先承诺速度提升。若框架成本超过收益，保留相同契约并使用小宿主，不因 dsh 使用 Cordis 就强制采用。任何选择先更新决策记录，再进入实现。

验证复用现有 Node 领域测试与 Electron 隔离工作区流程，新增契约兼容和生命周期回归；既有示例守卫、教务导入、单次调停课、对象引用、清空重启、复制 data/恢复均不可退化。代码阶段执行维护约定的公共检查与对应 Desktop 测试；纯设计阶段只检查文档。产品流程与总顺序见[随记](../product/随记功能与开发流程.md)及[路线图](../ROADMAP.md)。
