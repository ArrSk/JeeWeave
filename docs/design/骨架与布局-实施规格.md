# 桌面端 · 骨架与布局接入实施规格

> **给 Codex 的施工文档。** 目标：把 `desktop/design-lab/` 里验证过的界面语言接进真实桌面端，让用户能在设置里先选**骨架**、再选**布局**，自由切换。
>
> 硬要求：**现有功能一个不少，且摆放妥当。** 不改业务逻辑、不改数据格式、不改插件契约。
>
> 撰写 2026-11-02。实施前请先通读 §2 的不变量；§11 是禁止项。

---

## 1. 名词（后文一律用这三个词）

| 词 | 含义 | 举例 |
| --- | --- | --- |
| **骨架** | 页面怎么被组织、怎么切 | `workbench`（工作台）/ `loom`（经纬） |
| **布局** | 骨架内部的具体排布 | 工作台下 7 种；经纬下 4 种 |
| **材质 / 配色** | 只影响颜色与纹理 | 8 套配色 × 4 种材质 |

现有项目里的「布局」（`layout.mjs` 的 7 种）保持原名，归到 **workbench 骨架** 下。

两个骨架下要能选的：

```
骨架 workbench（现有）        骨架 loom（新，经纬派）
  └ 布局 7 种                   └ 布局 4 种
      sidebar / rail / top           ripple  涟漪
      float / dock / island          atlas   舆图
      focus                          stage   夜场
                                     jingwei 经纬
```

> **为什么 4 种布局放在 loom 下**：这四套都建立在「插件清单驱动导航 + 不以侧栏为默认」这个前提上（见 `design-lab/plugs.js`），它们共享同一套导航契约，只是信息组织不同。workbench 的 7 种都保留固定侧栏/顶栏，属于另一种前提。

## 2. 不变量（违反即返工）

1. **数据格式不变**：`workspace.json` 的 `schemaVersion`、所有字段、迁移包格式一律不动。
2. **插件契约不变**：`moduleKey`、`builtinModules` 的 id/name/requires/suspended、`isModuleEnabled` 语义不动。
3. **命令不变**：`commands()` 注册的命令名与参数一律不改（`items.edit`、`courses.settings`、`plugins.set` 等），只允许**新增**骨架相关命令。
4. **IPC 与安全不变**：`contextIsolation`、`sandbox`、preload 白名单、CSP 一律不动。
5. **默认行为不变**：老用户升级后打开，**看到的就是今天的样子**（workbench + sidebar）。读不到骨架偏好时默认 `workbench`。
6. **13 页全可达**：§8 的摆位表是验收基准，任何布局下少一页都算失败。
7. **不为新骨架重写业务**：所有页面仍由现有 `createXxxUI()` 构造，新骨架只负责「容器 + 导航 + 切页」。

## 5. 接入方式（DOM 与切换）

### 5.1 `prototype.html` 的改动（唯一的结构改动）

在 `<div class="shell">` 上包一层，并给根节点加属性：

```html
<div class="shell" data-skeleton-host>
  <aside class="sidebar">…（保持原样，一个字不改）…</aside>
  <main class="main">
    <div class="loom-surface" id="loom-surface" hidden></div>   <!-- 新增，loom 骨架的内容容器 -->
    …（原有 section 全部保持原位）…
  </main>
</div>
```

根节点属性由运行时写入：`<html data-workspace-skeleton="workbench|loom" data-loom-layout="ripple|atlas|stage|jingwei">`。

**要点**：原有 13 个 `<section>` 一个都不移动。loom 骨架工作时，它们仍然在 `.main` 里，只是被 `.loom-surface` 遮住/替换显示（见 5.3）。

### 5.2 为什么用「保留 DOM、只换显示」而不是「重建 DOM」

- 现有 `host.page(id, {enter})` 里的 `hideBaseViews()` 依赖这些 section 存在；
- 插件运行时（`reminders`）会把页 append 进 `.main`，重建容器会让它们的引用失效；
- 现有测试（`design-integration.cjs`、`chrome-interaction.cjs`、`next-development.cjs`）大量断言 `.sidebar`、`.shell`、`[data-workspace-layout]` 的存在。

保留 DOM 后，**workbench 骨架的行为与今天完全一致**，测试零改动。

### 5.3 `skeleton-runtime.mjs` 的职责

```js
// 伪代码，按此实现
export function createSkeletonRuntime({ host, root, main, storage, feedback }) {
  read()      // 读偏好；缺省 workbench
  apply(next) // 见下表
  dispose()   // 卸载 loom 的监听/观察器/定时器
  return { refresh, dispose, current: () => state };
}
```

`apply()` 要做的：

| 步骤 | workbench | loom |
| --- | --- | --- |
| 1. 写根属性 | `data-workspace-skeleton=workbench`，`data-loom-layout` 清空 | 写 `loom`，并写 `data-loom-layout` |
| 2. 侧栏与工具栏 | 显示（沿用 `desktop-design.css`） | **隐藏**（`[data-workspace-skeleton=loom] .sidebar{display:none}`），工具栏同样由 CSS 收起 |
| 3. 内容容器 | `.loom-surface` 隐藏，原有 section 按 `host.page` 显示 | `.loom-surface` 显示；原有 section **全部隐藏**；loom 把**同一个 section 节点**移进 surface 并显示 |
| 4. 导航 | 复用现有 `.nav [data-view]` | 由 `loom-nav.mjs` 渲染（见 §8） |
| 5. 切页 | 现有 `host.navigate()` 不变 | 拦截为 `loomNav.go(id)`，内部仍调 `host.navigate(id)` |

**第 3 步的实现方式（重要）**：不是克隆，而是**移动节点**。切到 loom 时，把当前要显示的 section 用 `appendChild` 移入 `.loom-surface`；切回 workbench 时，按 `pages` 注册表顺序 append 回 `.main`。移动前记录原 index，切回时插回原位，保证 workbench 的 DOM 顺序不变。

> 这样做的收益：**同一个页面对象**在两种骨架里都是活的，表单状态、滚动位置、事件监听全部保留。

### 5.4 `prototype-modules.js` 只改这 4 处

| # | 位置 | 改动 |
| --- | --- | --- |
| A | `:735-762` 的 `enter` 回调 | 在 `hideBaseViews()` 之后、`target.hidden=false` 之前，插入一行：`skeleton?.beforeShow(id)`；显示之后插入 `skeleton?.afterShow(id, target)`。**不改变原有逻辑**，只是给骨架一个挂钩。 |
| B | `:302` `hideBaseViews()` | 追加 `.loom-surface` 内页面的隐藏（或统一改为「遍历 `pages` 全部隐藏 + 清空 surface」）。**新增页面时必须同步**。 |
| C | `:614-616` 三个 `createXxxUI` **之后** | 追加 `createSkeletonUI({ container, storage, feedback, onChange })` 并 prepend（**必须在 desktopDesign 之后**，否则骨架会掉到最底，见 §7.1）。 |
| D | `:1082` 起手处 | `const skeleton = createSkeletonRuntime({...})`，并在 `pagehide` 时 `skeleton.dispose()`。 |

除这 4 处外，**`prototype-modules.js` 不得有其他改动**。

规则：

## 7. 设置里的两级选择（`skeleton-ui.mjs`）

### 7.1 插入顺序（**容易做反，必看**）

`container.prepend()` 是「插到最前面」，所以**后 prepend 的在上**。现有三处（`prototype-modules.js:614-616`）按 appearance → reading → desktopDesign 的顺序 prepend，最终从上到下是：

```
布局与动效（desktopDesign）  ← 后 prepend 的在上
阅读与显示（reading）
配色与文字（appearance）
```

要得到「骨架 → 布局 → 阅读 → 配色」，**`createSkeletonUI()` 必须在 `createDesktopDesign()` 之后调用并 prepend**：

```js
// prototype-modules.js:614-616 之后追加
const appearanceUI = createAppearanceUI({...});   // 原第 1 个 prepend
const readingUI = createReadingUI({...});         // 原第 2 个
const desktopDesign = createDesktopDesign({...}); // 原第 3 个 → 原最上
const skeleton = createSkeletonUI({ container: settingsPanel.querySelector('.desktop-settings-panel'), storage, feedback, onChange })  // 新，最后 prepend → 新最上
```

> 若按「先建骨架」的顺序写，骨架会掉到最底部。**这是本阶段最容易犯的一个错**，验收时请直接看设置页截图确认顺序。


### 区块结构

```
骨架
┌────────────────────────────────────────────────┐
│  [卡] 工作台            [卡] 经纬                          │
│  固定导航 + 内容区。     导航随布局变化。                    │
└────────────────────────────────────────────────┘
   ↳ 选了工作台 → 下方「布局与动效」显示 7 种（现有 UI，不动）
   ↳ 选了经纬   → 下方「布局与动效」切换为 4 种（本文件新增）

布局（经纬时）
┌──────────┬──────────┬──────────┬──────────┐
│ 经纬      │ 涟漪      │ 舆图      │ 夜场      │
│ 一条经线   │ 一条河面   │ 一块疆域   │ 一个舞台   │
└──────────┴──────────┴──────────┴──────────┘
```

**实现方式**：`desktop-design.mjs` 里的 7 种布局卡片**不删**，只在外层包一个 `<div data-skeleton-section="workbench">`；`skeleton-ui.mjs` 新增 `<div data-skeleton-section="loom">` 放 4 种。切换骨架时用 `[data-workspace-skeleton]` 的 CSS 控制显示哪一组，**不重建 UI**。

**无障碍要求**：
- 两组都是 `role="group"` + `aria-label`；
- 卡片是 `<button aria-pressed>`，选中态可读；
- 切换骨架时，把焦点移到新显示那组的第一个按钮，并 `role="status"` 播报「已切换到经纬骨架 · 经纬布局」。

### 8.1 全局可达性规则（三选一，每个布局必须至少满足一条）

1. **常驻导航**：页在导航里能点到（workbench、loom-strip 顶栏、loom-atlas 图例）。
2. **命令面板**：`Ctrl K` 输入页名可直接到（四个 loom 布局**全部必须**实现）。
3. **就地入口**：页面在某个主视图里有明确按钮（如 `objects` 可从今天某条的「所属对象」进入）。

> **不许**只靠一条深层路径。每页至少满足 2 条。

### 8.2 必须保留的既有入口

现有代码里有若干「程序化跳转」，换骨架后**必须仍然生效**（它们都走 `host.navigate()`，只要骨架不拦截 `navigate` 就不会坏）：

- `today` 里点课程 → `courses`（`:611`）
- 事项编辑 → `plans`；对象 → `objects`（`:1028-1029`）
- 网页采集 → `web-capture`（`:1032`）
- 助手 → `settings`（`:1072`）
- 提醒 → `reminders`（`:1073`）
- `settings.open` / `plugins.open` / `today.open` / `calendar.open` / `overview.open`（`:1059-1068`）

**验收时逐条点击**，确认 loom 下也能到。

## 9. loom 骨架的实现要点

### 9.1 导航（`loom-nav.mjs`）

四个布局各有一套导航，但**都遵守同一契约**：

```js
createLoomNav({ layout, host, main, surface, feedback })
  → { render(visiblePages), go(id), dispose() }
```

| 布局 | 导航形态 | 要点 |
| --- | --- | --- |
| `jingwei` | 右缘三道横纹（三个尺度）+ 左缘线头 + `Ctrl K` | 尺度=页面映射：现在→today、本周→courses、长线→objects |
| `ripple` | 顶栏「今天/本周/事项/笔记/对象」+ 底部日/周/月 | 底部尺度相当于 workbench 的日历粒度，不是页面 |
| `atlas` | 顶栏三个图层（地块/路线/界标）+ 左缘图例 | 图层→页面映射：地块→objects、路线→today、界标→plans |
| `stage` | 顶栏灯位 + 右侧候场列 + 底部幕线 | 候场列列出全部可到达页 |

**四个布局都必须**：
- 从 `modules.mjs` 的 `isModuleEnabled` 读哪些插件开着，关掉的页**不出现在导航里**；
- 挂起的 `chat-monitor`、未实装的 `ledger` 有独立标记；
- 提供 `Ctrl K` 命令面板（可复用 `search-ui.mjs` 的服务与记录路由，或新写一个轻量面板，但**必须**走 `host.navigate`）。

### 9.2 内容容器

loom 的四种布局**不重写页面**，只重排：

- `jingwei`：section 直接放在经线右侧（单列，宽度 `min(820px, …)`）
- `ripple`：section 放在主水面区，左侧留时间轴
- `atlas`：section 放在图层主区，左缘留图例
- `stage`：section 放在台上区，右侧留候场列

**做法**：`.loom-surface` 用 CSS Grid，四种布局各一个 `[data-loom-layout=…]` 的 grid 模板；section 作为 grid 子项。**不改 section 内部任何样式**（第一期），第二期再逐步给经纬换皮肤。

### 9.3 样式隔离

`loom-shell.css` 的**每一条规则**都必须以 `[data-workspace-skeleton="loom"]` 或 `[data-loom-layout=…]` 开头。凡是不带前缀的选择器，一律视为错误（会在 workbench 下污染）。
