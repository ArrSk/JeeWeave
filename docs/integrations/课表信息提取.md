# 课表信息提取与来源边界

更新：2026-10-19。对象是学校原始课表，目的是准确导入排课安排；课程不会被自动转换成待办。

## 当前 Desktop 实现

用户在应用内手动完成南邮 WebVPN/身份认证，查询学生课表，再回几微点击“抓取并导入”。程序优先用隔离环境读取当前页面，需要时读取帧树并使用正文兜底。

列表按行列和合并单元格还原，网格作为核对与备用来源，正文继承同星期内的节次。关键字段和周次必须有效，数量不完整或列表/网格安排冲突时整批拒绝；单双周不同教室仍是独立安排，教师/地点读取图标旁的实际文字。

去重后直接加入本次选中的课表，不要求学校页面注入按钮或先导出 HTML。未指定星期节次的“其它课程”保存在待安排清单，不虚构时间。已知南邮来源只校正通用默认作息，自定义作息保留。

课程抓取原文不自动作为 TXT/HTML 落盘。清理后的原页面可在应用内查看，开发者模式显示原始文本和读取状态；私人样例和业务资料不进入仓库。

## 对象设计的后续要求

一项排课安排不等于整门课程。之后需要可靠的学期/课程/教学班身份，或用户确认分组，才能把多项安排归到同一课程；不能仅按课程名自动合并。重复抓取与调整要保留旧 ID 和关联，契约见[对象关联与迁移](../design/对象关联与迁移.md)。此关联尚未实现。

## 普通网页与 AI 的边界

普通公开静态网页整理独立保存原文、重点和行动草稿，用户确认后才加入待办。没有外部模型调用、通用笔记库，也不保证处理登录后或动态网页。

未来模型只处理明确同意外发的必要内容，生成有来源证据的候选，再经过校验与确认；不发送账号、Cookie、密码、验证码或完整登录页。可用规则解决的表格继续用规则。旧方案中的统一收件箱、AI 和任意学校适配不能当作现状。
