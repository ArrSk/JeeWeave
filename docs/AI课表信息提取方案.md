# AI 课表信息提取方案

状态：课程表网页读取已加入南邮表格归位修复；网页通知的本地重点提取和待批准草稿已接入，真实模型仍默认关闭。

2026-10-17 桌面现状更新：南邮 WebVPN 课表采用用户已验收的直接抓取导入流程。普通网页整理已恢复到桌面独立“网页采集”页面，保存公开静态页原文并用本地规则提取重点、日期与行动草稿；用户可修改标题/日期后确认加入桌面待办，保留来源与证据。信息型内容保存在网页记录中，尚未写入笔记模块；下文早期的统一预览/收件箱方案不应当作当前桌面入口说明。

## 当前已经能做什么

桌面端通过受限窗口打开用户指定的教务网址。用户自己完成登录并打开个人课表后，点击“允许读取当前课表页面”，程序读取当前页面的 HTML 表格，提取课程名、教师、教室、星期、节次和周次，生成可编辑预览。确认前不会写入课表，读取失败也不会修改原数据。

当前默认入口是南京邮电大学登录地址。其他学校可以先手动填写网址；不同学校页面结构不同，不能保证同一套规则直接适配。

## 网页采集后的重点与草稿

公开网页采集完成后，采集器会在本机先做一次“重点提取”：按截止日期、行动词和重要提示给正文行打分，保留原文证据，并把明确日期转成待办草稿。没有明确日期但包含“提交、报名、申请、确认”等动作的内容，也会生成没有截止日的待办草稿；只有重点而没有行动时，会生成笔记草稿。

桌面端会同时显示“重点”和“建议草稿”。每条草稿都带有来源网页、原文证据、类型、截止日期和置信度。用户点击“批准加入”后，草稿才会写入本机待整理收件箱；当前还不会绕过用户确认直接写入正式计划、待办或笔记库。

这一步叫做 AI 的“可替换前置层”：现在使用本地规则，离线可用、不会上传登录内容；将来接入模型时，只替换提取器，仍要求模型返回结构化草稿，并继续经过字段校验、来源证据、重复检查和用户批准。模型不可用时，本地规则结果仍然保留。

## AI 应该怎样加入

第一层是固定规则。先识别表头、星期、节次和周次，能用规则得到的字段不交给模型。这样结果稳定、成本低，也能在没有网络时继续运行。

第二层是候选提取。遇到合并单元格、课程信息写在一段文字里、教师和地点顺序变化时，把必要的单元格文字组成候选文本，只发送用户明确同意的内容给模型。模型只能返回结构化草稿：课程名、教师、地点、星期、开始节、结束节、周次和不确定字段。

第三层是校验和确认。模型输出必须经过现有课程字段校验、周次范围检查、重复检查和时间冲突检查。每个不确定字段显示原因和原文证据，用户修改并确认后才写入 `Block`。

## 隐私和失败处理

- 不把账号、密码、Cookie、验证码或完整登录页面发送给模型。
- 默认只发送课表表格的必要文字，发送前显示字段预览。
- AI 不直接调用数据库写入，也不能执行网页里的指令。
- 模型不可用、额度不足或解析失败时，仍保留规则结果和手动编辑入口。
- 外部模型调用以后再做，先提供本地规则预览，避免现在引入密钥、服务费用和数据传输风险。

## 分阶段实现

1. 用假课表 HTML 覆盖常见表头、合并单元格、单双周和缺失字段（已补充南邮式表格测试）。
2. 把网页解析结果统一转换为现有 `CourseImportRow` 草稿（已完成）。
3. 增加“提取建议”预览，明确标出来源文字和不确定字段（网页通知已完成）。
4. 接入一个可替换的 AI provider 接口，默认关闭，逐次确认发送内容。
5. 最后再考虑学校适配器和图片识别，共用同一套草稿、校验和确认流程。
