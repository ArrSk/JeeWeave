# 当前架构与插件化演进

更新：2026-10-20。本文将**实际运行架构**和**设计目标**分开。旧长篇架构、历史技术选型及界面变更记录移至[历史架构快照](history/ARCHITECTURE-20261019.md)，不据其中的规划表宣称功能已完成。

## 目前真实运行的部分

| 层 | Desktop 当前实现 | Web 当前实现 |
| --- | --- | --- |
| 界面 | Electron 加载 HTML/CSS/ES Modules | React/Vite/PWA |
| 业务 | 课表、今天、统一事项、派生日历、公开网页整理 | 课程、计划、待办及自己的界面 |
| 存储 | 主进程版本化 workspace.json，原子替换；localStorage 为缓存兼容 | data 仓储与 Dexie，经服务读取 |
| 时间规则 | 复用 core 的上海日期/教学周模块，桌面 planning/calendar 纯规则 | core Block/Occurrence 与 data 展开 |
| 平台能力 | preload 受限 IPC、教务视图、文件和窗口 | shared platform 当前 Web 实现 |

两端目前各自保存业务数据，不能互相恢复备份；Desktop 尚未统一迁入 React/Dexie。技术栈、IPC、图标、标题栏和验证入口以 [Desktop README](../desktop/README.md)、[Web README](../web/README.md)为准。

## 已有模型的职责

- Desktop `courses[]` 是一项排课安排，同一门课可能有多项；`unplacedCourses[]` 保存无明确星期/节次的教务记录，不生成假时间。
- Desktop task/plan 共用 planning 规则和“事项”界面，仍分别存在 tasks/plans 集合中以兼容来源和 ID；kind 不限制时间类型。事件/考试共用一个选项，兼容旧考试标签，不另建事件库；分类按 anchor，事件/考试、截止、区间、重复和阶段共用编辑。
- Desktop object-view 以可选 objectView 存课程/项目/主题和精确来源引用；object-view-ui 聚合原课程、事项、网页正文，不另存正文或完成状态。引用包含集合，排课引用另含课表 ID；一条来源一个主归属，编辑事项与归属同次事务。来源删除保留可解除的提示，不能误关联新同名记录。对象视图是 Beta，不含单次课作业来源和多执行时段。
- examples 统一开发者模式守卫与示例可见性；读取投影过滤、完整集合写回，关闭开发者模式不删除任何示例。
- Desktop calendar 从既有事项及课表有效课次/调停课标记派生，不另存课程或完成状态。课表可选 adjustments 以课程 ID 与原日期建立身份，修改调入时间不重编号；今天和 ICS 同源。
- Web Block 表示时间模板，Occurrence 可重建；Note 等类型的存在不代表 Desktop 已有完整笔记、记账或提醒功能。
- data、会话、原文、导出和备份统一在桌面 data 目录，格式与兼容边界见[数据格式](../desktop/DATA_FORMAT.md)。

## 本轮设计的改变：增加组织上下文

对象回答“围绕谁”，事情回答“要办成什么”，活动和安排回答“什么时候发生、什么时候投入”。时间模板仍负责时间，不能负责所有目的、资料和费用。

2026-10-20 已实现对象视图 Beta，提供手动主归属、聚合详情及课程/事项/网页双向跳转；不把课程拆成待办、不复制事项库。更多相关对象、单次课布置来源、多段独立投入与今天按事情组织仍是后续设计，不能以 Beta 替代完整领域方案。

产品语言、示例和页面分工见[对象与事情设计](product/对象与事情设计.md)；字段、身份、查询、删除和迁移见[对象关联与迁移](design/对象关联与迁移.md)。

## 分层约束

1. core 保持纯函数，未来增加对象/引用/逻辑课次规则，不依赖 DOM、数据库或网络。
2. data 提供对象与关联查询、引用校验和原子用例；时间/课程调整后按既有规则重建课次并通知读取方。
3. ui 保留可复用展示契约；各功能模块不直接导入彼此的实现。
4. Desktop 可先通过既有 Storage/主进程接口适配关联服务，不借本任务更换数据库或 UI 技术栈。
5. 关系的唯一来源、稳定 ID、完成语义、失败回滚与备份兼容先明确，再增加总览视图。

## 当前与下一步的边界

已验证的运行基线与 0.2.1 交付状态见[交接说明](HANDOVER.md)。对象详情和主归属已提供 Beta；多执行时段、通用文本分类、记账与随记仍按[路线图](ROADMAP.md)推进。保持原文件 schema 与事项两份集合，关联有自己的子版本；上述后续设计不代表已经实施或迁移用户实际资料。

## 新增目标：最小宿主与业务插件（待实施）

底层重整的目标是为插件之间提供稳定接口：宿主管运行、服务路由、生命周期、平台权限与持久化机制；课程、事项、对象、随记、日历/今天及采集导入提供各自的业务能力。领域规则由业务提供者负责，宿主不集中硬编码所有业务模型。纯时间函数继续复用 core。

查询读取权威提供者的版本化投影，命令返回明确结果，事务提交后再发送变化事件。引用沿用稳定集合/id/课表范围；聚合界面读取原记录，不复制正文或完成状态。各插件通过统一导航与 UI 贡献进入原编辑器，生命周期撤销注册，避免关闭后页面残留。

先在现有 workspace/preload 上加适配、用随记与对象/事项验证互通，再逐功能替换跨模块私有读取。Desktop 继续使用现有 HTML/CSS/ES Modules，Web 现有 React FeatureModule 需适配，不能直接充当平台无关协议。命名空间、备份、迁移和开发者清空仍统一在 data 内；不创建散落个人数据目录。

当前模块开关不是完整插件框架；同进程内置插件也不是第三方安全隔离。框架尚未选定，DeepSeek Harness/Cordis 仅作已核对的参考，第三方插件隔离、安装与 SDK 留待后续。详细契约与渐进验收见[底座设计](design/插件化底座与迁移流程.md)，随记数据草案见[随记流程](product/随记功能与开发流程.md)，决策见 ADR-016。
