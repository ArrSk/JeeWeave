## 底层职责与产品方向

产品以对象与事情保留背景和目标，课程与学习是首先落地的场景。宿主负责连接能力，业务规则由各插件提供；课程表不承担其他功能的总入口或所有数据的父容器。

| 部分 | 职责 |
| --- | --- |
| 宿主与插件运行时 | 依赖、版本、公共服务/命令、事件、导航、启停与资源清理 |
| 数据与引用机制 | 稳定身份、原记录、持久化、兼容与恢复；按已支持的用例提交关联写入 |
| 业务插件 | 各自管理课程、事项、笔记、提醒等规则，通过公共接口互通 |
| 聚合视图 | 今天、日历与对象视图从提供者读取原内容，保留来源与唯一完成状态 |
| 平台适配 | 对接各端的文件、窗口、输入、系统通知与权限边界 |

AI助手也是可选插件，通过公共命令生成草稿并确认执行，不另设一套业务存储。业务可独立使用，关联按需建立。现有内置插件宿主已落地；任意跨插件事务、完整多对象关系、跨端统一数据与第三方安全隔离仍未全部实现。愿景不要求现在统一技术栈或重写现有存储。

## Desktop 助手边界（2026-10-29）

文本默认DeepSeek V4.1 Flash-1017（API名deepseek-flash），当前输入+精选相关字段正常一次生成最多8步可编辑草稿；格式校验失败最多额外一次纠正，单次操作共用60秒时限、汇总用量，推测以assumptions展示；不上传完整工作区。API配置仍在主进程Windows加密。确认后由本地草稿执行器调用host注册的公共命令和原服务；新记录引用仅从实际成功结果解析，不编造已有ID。保留已完成项，失败后只续做剩余步骤；跨插件整批不保证原子性，执行进度目前只在面板内保存，不是持久工作流引擎。没有配置或请求失败保留本地笔记草稿并明示，不能当成模型成功。

## Desktop 输入功能的独立插件（2026-10-29）

全局助手与提醒分别注册assistant/reminders内置插件，只要求workspace，不互相作为硬依赖。每个插件声明自己的公共服务、命令、能力和生命周期；助手经公共服务访问提醒和其他业务。界面在运行时effect中挂载，关闭即清除命令/页面、观察器、计时器和入口；助手的业务调度/目录/相关索引从prototype-modules移至assistant-plugin。提醒的UI、纯规则和存储/OS调度单独成文件，不由助手创建。

主进程分别创建两个平台实例，保留旧IPC契约作为路由；本地页面和插件开关双重校验。关闭助手中止API请求；关闭提醒串行取消OS任务而不删记录，重新开启只恢复未来/每日任务；worker在投递前读取workspace中的reminders开关。排队但尚未开始的提醒写入也会重新检查状态。密钥、提醒和模块偏好仍在原data目录，不迁移数据文件或提高workspace版本。

## 已有模型的职责

2026-10-25 增加 `mobile/` Android Beta 宿主，具体见 [手机版说明](../mobile/README.md)。构建时按 Desktop 运行白名单复制纯渲染资源和轻量 core 日期模块；`mobile-entry` 在启动前注入原存储桥契约，然后加载同一插件运行时。手机只替换布局与平台边界，不复制任务、笔记或对象模型，不依赖 Electron 或 React/Web 数据库。Java Activity 只服务包内 HTTPS 虚拟源资产，同步保存由 AtomicFile 完成并检查 revision；文件导入在 JS 中复用原完整校验、预览与确认。本地缓存仍非权威。CSP 禁远程脚本/iframe，主工作区 WebView 拒绝网络请求；beta.2 在无本地桥的独立 PortalPage 承载 HTTPS 教务登录与抓取，APK 仅为该页面增加 Internet 权限。公开网页在线抓取仍未移植。shared/packages/platform 目前仍只有 Web 实现，不能把独立的 Android 原生宿主写成该包已经完成适配。

- Desktop `courses[]` 是一项排课安排，同一门课可能有多项；`unplacedCourses[]` 保存无明确星期/节次的教务记录，不生成假时间。
- Desktop task/plan 共用 planning 规则和“事项”界面，仍分别存在 tasks/plans 集合中以兼容来源和 ID；kind 不限制时间类型。事件/考试共用一个选项，兼容旧考试标签，不另建事件库；分类按 anchor，事件/考试、截止、区间、重复和阶段共用编辑。
- Desktop object-view 以可选 objectView 存课程/项目/主题和精确来源引用；object-view-ui 聚合原课程、事项、笔记、网页正文，不另存正文或完成状态。引用包含集合，排课另含课表 ID；一来源一主归属，事项与归属同次事务。对象可填写完成标准，事项保存 goal/completionCriteria 与 courseOrigin（课表/课程/原日期及标题快照）；来源删除保留提示，不重连同名新记录。
- examples 统一开发者模式守卫与示例可见性；读取投影过滤、完整集合写回，关闭开发者模式不删除任何示例。
- Desktop calendar 从既有事项及课表有效课次/调停课标记派生，不另存课程或完成状态。课表可选 adjustments 以课程 ID 与原日期建立身份，修改调入时间不重编号；今天和 ICS 同源。
- Desktop journal 以可选子版本保存文字、日期、分类、标签、修订、编辑/提炼草稿；稳定身份、归档/回收站与对象引用保留。确认提炼由 items 服务原子提交原事项、主归属及确认状态，不在笔记内复制事项。停用释放资源并保留数据。
- Web Block 表示时间模板，Occurrence 可重建；Note 等类型的存在不代表两端已有完整知识库、记账或提醒功能。
- data、会话、原文、导出和备份统一在桌面 data 目录，格式与兼容边界见[数据格式](../desktop/DATA_FORMAT.md)。
- Desktop 迁移包由主进程 workspace-transfer 负责选取后的读取、校验和原文落盘；渲染层只发起预览/确认，业务提交复用 prepareWorkspaceRestore 与 workspace-file 原子备份，成功后 adopt 已保存快照。应用版本不等于存储格式版本；未知新格式拒绝，旧格式集中转换。

## 本轮设计的改变：增加组织上下文

对象回答“围绕谁”，事情回答“要办成什么”，活动和安排回答“什么时候发生、什么时候投入”。时间模板仍负责时间，不能负责所有目的、资料和费用。

对象 Beta 提供手动主归属、聚合详情与原功能跳转；课次来源按原日期识别，事项可设多段独立投入，今天按原事项汇集。阶段时段可挂 phaseId；重复时段挂 occurrenceDate，完成原定那次而非执行移动后的日期。多对象、自动整组排期与完整领域工作台仍未实现。

产品语言、示例和页面分工见[对象与事情设计](product/对象与事情设计.md)；字段、身份、查询、删除和迁移见[对象关联与迁移](design/对象关联与迁移.md)。

## 分层约束

1. core 保持纯函数，未来增加对象/引用/逻辑课次规则，不依赖 DOM、数据库或网络。
2. data 提供对象与关联查询、引用校验和原子用例；时间/课程调整后按既有规则重建课次并通知读取方。
3. ui 保留可复用展示契约；各功能模块不直接导入彼此的实现。
4. Desktop 可先通过既有 Storage/主进程接口适配关联服务，不借本任务更换数据库或 UI 技术栈。
5. 关系的唯一来源、稳定 ID、完成语义、失败回滚与备份兼容先明确，再增加总览视图。

## 当前与下一步的边界

最新交付为 0.3.0，包含笔记 N1/N2、普通事项多时段与迁移包；本轮本地扩展课次来源、阶段/重复安排和公开提供者聚合查找。查找由 workspace 注册 search，调用业务公开查询而不读私有键；按类型/主归属与关键词过滤，不新增索引或正文副本。通用知识库、记账、外部插件与跨端数据互通仍按[路线图](ROADMAP.md)推进。保留外层 schema 与事项两份集合，没有迁移用户实际资料。

## 内置插件底座（现有 Desktop 业务已统一接入）

2026-10-21 按用户“全部改造”的新范围完成当前内置业务的数据、互通和生命周期迁移；此前小步记录不再代表当前缺口。Electron、HTML/CSS/ES Modules 与原界面保持，Web 独立。完整入口、契约与图示见[内置插件接口](development/内置插件接口.md)。

- workbench-host 管服务版本、命令、页面、事件与 scope；plugin-runtime 按清单/依赖激活，拒绝循环与错版，失败释放本次注册。停用撤销服务、命令、监听、周期定时器及平台订阅，重新开启只安装一份。旧 use 代理永久失效，UI 的 client 每次重连。
- workbench-services 是提供者组合入口；课程读写/批量/作息/调停课/文件和教务导入、事项、对象编辑与聚合、笔记、网页采集均经领域服务。今天、日历和总览经聚合提供者查询，失败来源有明确提示，其他来源继续显示。prototype-modules 保留既有界面与装配，不持有业务集合读写权限。
- record-router 按 collection/id/课表范围检查原记录，再路由所属功能命令；跨模块不模拟按钮点击。found/missing/hidden/disabled/unavailable 分开，关闭不删除关系，缺失不找同名替代。
- plugin-storage 按声明检查键和关联事务权限；设置 UI 只有偏好键。旧示例来源兼容仅提供 URL/taskId 元信息，不暴露其他提供者的网页正文。原型存储方法保留接收者，事务回滚读取完整原文，不能用展示投影替代备份。
- 原 workspace/preload 继续作为权威适配器，所有数据仍在同一 data。恢复在内存准备旧课表/选择后一次提交，失败不留下半恢复状态；旧 ID、未知扩展、tasks/plans、正文/草稿和外层 schema 均保留。事件提交后才发送来源/修订/序号等元信息，观察者或诊断失败不冒充写入失败。
- 网页与教务长操作携带代际令牌，关闭再开启也不能接收旧结果；UI 旧回调不覆盖新忙碌状态。主进程 platform-permissions 再查本地主框架、功能开关及工作区代际，网页原文落盘前再次校验，教务停用释放原窗口/视图。原网络超时保留，不宣称已中止远端请求。

事项归属与网页确认继续通过同一工作区内的同步准备/原子提交，准备不能写存储、异步等待或覆盖事项集合；不是分布式事务。课程编辑、批量、作息和导入检查绑定快照，隐藏课程及其调整在可见编辑时保留。笔记保存失败继续拦截切页、停用与退出。

当前是可信内置代码的完整迁移，能力声明不等于第三方沙箱。第三方隔离/安装/SDK、Web 运行时适配与多对象关联仍未实现。本轮没有新增框架依赖、封装或发布；公开 v0.3.0 保持原交付。运行事实见[交接](HANDOVER.md)，取舍见 ADR-019/021/022。

## 2026-10-30 · 诊断与提醒同步完善

保留同步宿主架构，新增只读运行时诊断：期望开关、实际状态、服务依赖/版本、可计数注册及最近激活/效果清理错误。host.inventory原返回结构不变，独立resourceInventory提供owner元信息。开发者模式下的插件管理按需展示；主进程对原生诊断另查本地页面与developerMode，允许在提醒关闭时读取暂停状态，不返回业务记录。

## 2026-10-30 · 桌面迁移与原生提醒

workspace-transfer继续组织业务及附件；reminder-transfer只负责可迁移字段、摘要/指纹和文件恢复日志，reminder-platform负责串行替换与目标设备系统任务。迁移包升到v2，工作区和提醒字段版本均保持1，v1读取兼容且缺少提醒时保留本机记录。主进程锁住迁移期间写入，启动先恢复日志再加载工作区，避免缓存读取半迁移资料；日志清理失败保留写锁到重启。

含提醒时先保存完整旧.jiwei，业务提交前失败恢复文件，提交后系统任务失败返回可见警告。原生OS不是跨文件事务参与方，不保证迁移中的提醒投递时效。密钥和登录隔离不变，Web与手机本轮不改；现有旧客户端拒绝v2。格式与备份位置见[数据说明](../desktop/DATA_FORMAT.md)。
