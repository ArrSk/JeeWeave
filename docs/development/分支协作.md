# 三端分支协作

作者：ArrSk。2026-10-29建立，共用同一Git历史，不拆成三个仓库。

## 分工与依赖

- main：共用代码、根配置、公共文档及验收后的集成基线。
- web：网页/PWA，主要修改web目录。
- pc：桌面主线，主要修改desktop目录。
- mobile：Android，主要修改mobile目录。

各分支都保留完整目录。mobile/prepare.mjs按白名单复用desktop业务和shared代码；删除其他端目录、建立孤立历史或提交三份shared副本都会破坏依赖或增加维护成本。分支隔离开发进度，目录划分源码职责。

共用修改由main提交一次，使用普通merge同步同一个提交；没有分叉时可用--ff-only。不要为同一共用修改分别复制提交，也不要用cherry-pick或squash重新生成三个提交。Git复用相同提交和文件对象；merge可能产生合并提交，但不会把共用文件重新存成三套独立源码。

## 日常操作

开始桌面开发：

```powershell
git fetch origin
git switch pc
git pull --ff-only
```

网页和手机将pc换成web或mobile。切换前保存当前工作；不要丢弃或覆盖未提交改动。

修改共用代码时，先在main上完成相关修改与验证，再提交和推送。回到端分支同步：

```powershell
git switch pc
git merge main
git push
```

分支已经独立演进时可能需要解决冲突，检查后正常提交合并；不要force push。仅切换分支不会自动更新其他分支。

单端功能在对应分支提交；验收后按需合并到main，共用修复再同步至需要的分支。桌面先开发、用户确认后再移植手机的约定继续生效；合并源码不等于完成手机适配或授权生成APK。

## 发布与数据

Pages保持从main发布，push按网页/共用依赖路径过滤；仅合入desktop或mobile源码不会触发网页部署。网页分支完成验收后合入main再上线，不要求改变GitHub现有Pages环境设置。

源码、文档及必要素材通过Git同步。data、测试profile、缓存、SDK/JDK、签名、exe/APK与release压缩包不提交；成品仍须单独授权上传Release。本次只推送源码分支，不上传本地exe或APK。

仓库package.json的author及新提交作者为ArrSk；旧提交与第三方资料原作者保持不变。新建分支不重写历史。默认分支main保留，本地后续桌面工作停留在pc。
