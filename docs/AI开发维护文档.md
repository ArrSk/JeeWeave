# AI 开发维护速查

这份文档只说明阅读顺序与维护方式；具体规则以 [AGENTS](../AGENTS.md) 为准，避免多处维护不同版本的要求。

## 接手与定位

1. 读 [HANDOVER](HANDOVER.md) 的当前状态、最新结果和未验证边界；检查 Git 状态，保留已有改动。
2. 产品能力看 [README](../README.md)，下一步看 [ROADMAP](ROADMAP.md)，不把规划或技能示例当作已实现。
3. 改数据/模块边界时读 [ARCHITECTURE](ARCHITECTURE.md)、[DECISIONS](DECISIONS.md) 和 [内置插件接口](development/内置插件接口.md)。
4. 找文件看 [目录速查](开发目录说明.md) 与 [用途索引](文件用途索引.md)，不要每次重新盘点整个仓库。

## 本项目的重点

- Desktop 是当前主线，复用现有 Electron/HTML/CSS；Web 为独立客户端，不顺带迁技术栈。
- 功能通过提供者/引用路由连接，不跨模块读私有存储或操纵 DOM。关闭模块撤销资源，数据与引用保留。
- 所有业务数据保持同一工作区与稳定 ID；多入口编辑同一记录。迁移、删除、恢复必须保留未知扩展，失败不产生半份数据。
- 数据迁移契约集中在 [桌面数据格式](../desktop/DATA_FORMAT.md)，使用方法集中在 [Desktop README](../desktop/README.md)；其他文档链接过去，不重复解释字段。
- 示例须受开发者模式双重控制。群消息继续暂停；第三方插件安装与同步仍未实现。Android已有Beta包，最新源码预览尚未打包，两者不能混为同一版本。

## 每个功能的开发流程（2026-10-30调整）

借鉴Harness的服务、依赖、可撤销资源和显式装配，继续使用几微已有轻量宿主。原始研究在E:/CodeAndProj/rea-study，项目只维护可执行的开发约定，不复制一套逆向报告。

1. **定一个场景和完成标准。** 说清用户从哪里进入、要办成什么、原记录由谁维护；先查已有功能，避免新增重复模块。
2. **涉及边界时补契约。** 在[内置插件接口](development/内置插件接口.md)记录本次服务的提供者/消费者、版本、参数与结果、同步/异步、错误和提交点。已有接口复用；纯界面小修无需另写接口。
3. **经原服务实现。** 页面、AI、今天/日历都使用公共命令或查询；原记录只由对应提供者维护。查询、业务提交和系统副作用分别处理，提交后的事件用于重读，不另存完成状态。
4. **登记资源并能解释状态。** 本次新增的监听、计时器、网络与平台句柄明确归属和清理方式。开关值与实际运行状态分开；诊断集中在开发者模式，不让普通用户承担技术细节。
5. **只验证相关路径。** 用隔离数据覆盖本次正常操作和实际受影响的错误、启停或恢复；异步操作核对取消/有界等待、旧结果失效、清理失败与重复注册。测试结束自动清理，无新变化不反复验证。
6. **交付体验与记录。** 记录改动、实际检查和未验证边界；先电脑体验，确认后移植。既有手机预览继续按用户反馈处理，打包/提交/发布分别等待对应授权。

新插件和跨边界改动使用完整流程；已有功能只补发生变化的部分，不要求每个按钮修改都审查全局、重新设计契约或运行全套测试。

### 单条公共契约的最少信息

| 内容 | 要回答的问题 |
| --- | --- |
| 身份与依赖 | 服务名/版本、提供者、消费者、必需和可选依赖是什么 |
| 输入和结果 | 接受什么参数，返回记录/引用还是异步结果，哪些校验由提供者负责 |
| 失败与关闭 | 不可用、参数错误、平台失败怎样区分；关闭时如何停止操作和处理迟到结果 |
| 数据与副作用 | 哪一步算提交成功，是否支持重复请求，失败如何保留原数据；系统副作用何时发生 |

当前同步scope清理、ticket与原生开关守卫已有基础；完整通用异步卸载、第三方安全隔离、持久Agent执行日志仍未实现。只在具体需求证明必要时逐步补齐，不因研究重建全部底座。

## 技能与工具

- 库/框架/API 用法按 AGENTS 使用 Context7；缺工具时记录「未完成 Context7 查询」，再用已有实现或官方文档核实。
- UI 按需用 Impeccable，先看现有界面。已失败且环境未变的加载器不反复尝试；沿技能允许的回退流程继续。
- 只在确需外部服务时启用相关插件。区分文件存在、插件安装、工具可调用和本次执行成功，不因接入而自动发布。
- 账号、Cookie、真实课表与个人资料不上传到外部服务；检查采用隔离虚构数据。

## 验证与收尾

日常单功能只运行受影响的测试与关联入口，先复用现有测试的局部分支；不每次运行全仓库验证。较大里程碑、封装或发布前再按 AGENTS 运行类型检查、单测、构建、smoke 和相应桌面流程。纯文档改动只查编码、链接和差异。

界面检查合并宽窄与关键状态，一批修正后最多一轮确认。无新变化不重复测试；不能把模拟输入法、旧日志或其他版本的结果写成真实验收。

收尾只在 HANDOVER 记录最新结果与边界；产品能力同步 README/ROADMAP，模型和关键选择同步架构/决策。长过程移入 history 并保持链接，原检查事实不改写。打包、推送、部署需要当前任务授权，开发反馈不自动授权发布。

历史环境故障不能作为当前跳过检查的依据；已有可靠替代方式时继续完成当前任务。
