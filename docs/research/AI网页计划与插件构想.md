## 1. 产品方向

几微继续以本地优先的个人时间管理为主线，新增一条可选链路：

```text
用户授权来源 → 插件获取资料 → 轻量分析 → 用户确认 → Block/Note/Alert 落库
```

产品不直接变成通用爬虫或全自动 Agent。网页内容必须在用户有权限、连接器声明权限并遵守来源规则时读取；AI 只提出结构化建议，实际写入和提醒由几微现有数据层与平台适配层完成。

## 2. 与现有模型的关系

- `Block`：承载网页事件、截止事项和准备任务；优先复用 `kind: event|task|exam`。
- `Occurrence`：承载事件或任务的具体时间展开，继续使用现有确定性 ID 和时区规则。
- `Note`：保存原始摘录、来源链接、分析结果和用户修订记录。
- `Alert`：承载截止前提醒、网页变化提醒和计划待确认提醒。
- `shared/packages/core`：只增加纯函数，例如候选事项校验、冲突检测和计划拆分，不依赖网络或模型。
- `shared/packages/data`：未来通过仓储接口保存 `Source`、`Capture`、`Suggestion`；不允许功能页直接操作 Dexie。
- `shared/packages/platform`：继续负责通知、文件、分享等设备能力。

第一阶段不新增独立服务器，不改变 IndexedDB 主存储，也不把 AI 结果视为事实数据；所有 AI 结果必须经过确认或标记为草稿。

## 3. 插件边界

插件分为四类：

1. **来源插件**：读取已授权网站、文件或订阅源，返回正文、链接、更新时间和权限范围。
2. **分析插件**：从标准化内容中提取日期、地点、要求、材料和变化；可以接入本地或远程模型。
3. **计划插件**：将已确认事项转成 `Block`、`Occurrence`、`Note` 和 `Alert`。
4. **输出插件**：ICS、Markdown、外部日历、通知等；写入外部服务必须再次确认。

建议的最小插件接口（后续实现时放入 `shared/packages/plugin-sdk`）：

```ts
export type JiweiPlugin = {
  id: string;
  name: string;
  version: string;
  capabilities: Array<'read-source' | 'analyze' | 'write-plan' | 'export'>;
  permissions: Array<'network' | 'calendar-write' | 'notification' | 'file-read'>;
  connect?: () => Promise<void>;
  read?: (input: { target: string }) => Promise<SourceCapture>;
};
```

插件不能直接访问数据库、授权令牌或任意执行代码；它们通过宿主提供的受限接口读写数据。

## 4. 轻量 AI 赋能

首版只做三种按需调用：

- **提取**：把网页正文变成结构化事实和证据片段。
- **拆分**：根据用户可用时间，把一个目标拆成少量准备任务。
- **解释变化**：网页更新后说明哪些事件、任务或提醒可能受影响。

普通程序负责去重、日期解析、时区换算、冲突检测、权限检查、保存和撤销。AI 输出示例：

```ts
{
  facts: [],
  suggestedBlocks: [],
  evidence: [{ quote: string, sourceUrl: string }],
  confidence: number,
  needsConfirmation: true
}
```

为控制成本，只有内容变化或用户主动点击时才调用模型；固定网站优先使用规则抽取；摘要和计划结果缓存到 `Capture`/`Suggestion`；用户修改记录先作为偏好数据保存，不立即训练模型。

## 5. 首个可验证场景

优先选择一个结构稳定的来源，例如课程通知或活动报名页：

1. 用户添加来源并确认权限。
2. 来源插件抓取并保存链接、正文摘要和更新时间。
3. AI 提取截止日期、地点和准备材料。
4. 用户审核候选事件和任务。
5. 几微创建已有类型的 `Block`、`Occurrence`、`Note` 和 `Alert`。
6. 来源再次变化时，显示影响说明，不自动覆盖用户已经确认的安排。

## 6. 隔离与演进规则

- 本构想属于增量能力，不能把“日历同步、网页抓取、AI”写成当前已实现功能。
- 实现时从独立分支开始，例如 `feature/jw-ai-planner`，不直接修改 `main`。
- 首个代码增量应先建立类型、仓储接口和假插件，再接入真实来源。
- 任何新增能力通过 `docs/ARCHITECTURE.md`、`docs/DECISIONS.md` 和 `docs/ROADMAP.md` 同步记录。
- 原有课程表、计划、待办和提醒的行为必须保持兼容；失败的插件或模型不能阻塞本地核心功能。

## 7. 暂不做

- 不默认爬取任意登录网站。
- 不绕过验证码、访问控制或站点限制。
- 不让 AI 无确认地修改日历或发送外部消息。
- 不在第一阶段引入独立云数据库、微服务或专用训练模型。
