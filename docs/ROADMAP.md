# 几微近期路线：围绕一件事推进

更新：2026-10-20。O1 的主归属与集中视图已提供 Beta；新增随记（N）与插件化底座（A）的待开发流程，以下均区分设计与实现。已有阶段规划和历次交付记录归档为[历史路线图](history/ROADMAP-20261019.md)，与本页冲突时以本页近期范围为准。

## 已有基础

## 待开发事项与范围

| 切片 | 用户能做什么 | 交付边界 |
| --- | --- | --- |
| O1：对象与主归属（Beta 已实现） | 新建课程/项目/主题，关联排课、事项和网页，从原功能返回对象 | 手动确认同门课的排课入口；一来源一主归属；归档/取消关联；单次课布置来源、相关多对象尚未加入 |
| A0/A1：底层重整（待开发） | 功能通过统一服务、命令、引用与生命周期协作 | 最小宿主和现有存储适配；先接对象/事项，不一次重写全部页面；框架未选型 |
| N1：随记（待开发） | 随时记录灵感、思考、经验总结，离线保存和回看 | 无必填标题/分类/对象；草稿、搜索/标签、归档/回收站、Markdown 导出；同一 data 内保存 |
| N2：随记关联（待开发） | 记录归到课程/项目，确认后提炼成事项并双向返回 | 原文与完成状态各自唯一；通过提供者接口保存引用，失败回滚，关闭模块不删资料 |
| O2：事情的执行安排 | 给一次作业安排多段时间，工作台按事情保留目标和上下文 | 完成状态唯一；区间、截止、阶段和重复分别保留；既有日历读取关联 |
| A2：逐模块迁移（待开发） | 课程、日历/今天、网页与导入逐步遵循相同接口 | 随各功能切片迁移、验证并保留回退；不先改 Web 技术栈或破坏旧 ID |
| N3/A3：后续扩展（未启动） | 随记附件/历史/回顾；可安装外部插件 | 分开验收，外部插件先有隔离/权限/兼容验证；不等于已启动插件市场 |
| 可选后续：资料与用途 | 将通知/讲义关联到课程和事情，查看原文与行动依据 | 单独确定范围；手动归类、单原件多关联、待确认；不依赖外部 AI 或聊天监听 |
| 可选后续：其他能力 | 实现记账后，在对象内查看相关记录 | 费用去重与显式分摊、资料来源、模块关闭保留关系；单独验收 |

推荐实施顺序：**A0 契约/选型实验 → A1 薄宿主与对象/事项适配 → N1 独立随记 → N2 关联与提炼 → O2 多段投入/工作台组织**。A2 随后按业务切片逐项推进，可与 O2 的对应边界同步；N3、A3 分别按需要启动。每步先验证再提供本地体验，不让整库重写成为随记可用的前提。

O1 已解决部分课程归属问题，O2 的既定目标继续保留。本次用户明确新增应用内“随记”规划，与之前仅整理项目说明文档的任务不同；当前完成的是范围与流程文档，不是随记成品或第三方运行时。

随记的用户过程、数据草案和 N1/N2 验收见[随记开发流程](product/随记功能与开发流程.md)；底座职责、通信/事务、禁用和 A0–A3 验收见[插件化底座](design/插件化底座与迁移流程.md)。[参考调研](research/随记与插件架构案例.md)已核对 DeepSeek Harness 官方仓库，并记录 Memos、Logseq、Joplin 与思源的借鉴边界。

## 每步共同的验收条件

- 在课程、事情、待办和相应视图间跳转，能说明为什么做、属于谁、什么时候投入和何时截止。
- 同名课不会误合并，同一事情不会因多入口/多时间段而重复完成、重复统计。
- 上课结束不完成作业，步骤完成不自动等于成果交付，调课不改作业截止。
- 独立待办继续可用；原 ID、日期、周次、重复完成、阶段、来源和备份均保留。
- 删除/归档、关闭模块、重开、清缓存、复制 data 和恢复失败都有明确且无损的行为。
- 随记不强制变任务，正文和草稿可离线保留；关闭插件不丢正文/引用，恢复包含未知或已关闭的命名空间。
- 插件通过版本化服务协作，提交后才通知；禁止跨模块读私有存储/操纵 DOM，卸载清理监听、按钮和后台任务。

详细示例见[对象与事情设计](product/对象与事情设计.md)，工程契约见[对象关联与迁移](design/对象关联与迁移.md)。

## 开发与交付顺序

设计与范围 → 代码和验证 → 本地体验 → 用户反馈 → 用户确认后封装 → 验证成品 → 获授权后提交/发布。设计文档完成不等于关联功能已实现；当前任务不授权打包、推送或修改既有 Release。

移动端、平台适配、AI、同步等长期方向继续保留在历史路线和研究资料中，推进前重新核实。外部插件仍排在 A3；当前不安装 Harness/Cordis，也不因规划授权抓取聊天、迁移真实资料或发布。
