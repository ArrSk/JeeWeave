# 几微 · 路线图

> 原则：**每个里程碑结束都要能真实用起来**——不做"只有内部进展、用户看不到东西"的阶段。
> 纪律：实现 M(n) 时**不写**任何 M(n+1) 的业务逻辑，只使用已就位的模型与接口。
> 相关文档：[架构设计](ARCHITECTURE.md) · [决策记录](DECISIONS.md) · [新手使用说明](使用说明.md#本地运行)

## 平台开发路线（2026-10-13 重排）

你当前没有 Mac 和 Apple 开发者权限，因此 Apple 原生 `.ipa` 暂不作为近期交付目标。产品先用同一套 React 网页完成核心功能，再由不同外壳承载：

| 顺序 | 平台层 | 先做什么 | 可交付结果 |
| --- | --- | --- | --- |
| P0 | PC 网页壳 | 左侧导航、宽屏工作区、键盘操作、桌面信息密度和设置入口 | 电脑浏览器可完整体验 |
| P1 | Windows 桌面壳 | Electron 主进程、preload 受限桥、菜单、窗口、教务辅助窗口 | 用户确认 UI 后再生成 portable/安装包 |
| P2 | 手机/平板网页壳 | PWA 安装、离线、触控、窄屏底部导航 | Android/iPhone/iPad 可直接使用 |
| P3 | Android 包 | 只在网页体验确认后接入 Capacitor 或 Android WebView 外壳 | APK；不要求 Mac |
| P4 | Apple 原生路线 | 有 Mac 和 Apple 开发者权限后再评估 Capacitor iOS 或 Swift 原生 | 单独立项，不阻塞网页和 Windows |

这条平台路线只改变交付顺序，不改变 M0–M8 的功能边界。每一阶段都遵循“代码 → 本地体验 → 用户确认 → 封装 → 提交 GitHub”；未得到用户确认，不生成 APK/Windows 包，也不推送 GitHub。

### P0/P1 当前架子

- 网页层：`web` 负责页面、模块开关和本地数据，电脑使用左侧功能栏，窄屏使用底部功能入口。
- 桌面层：`desktop/main.cjs` 负责窗口、菜单、快捷键和受限 IPC；`preload.cjs` 只暴露教务登录/读取两个明确方法。
- 教务辅助窗口只在用户主动打开并确认读取后工作，账号密码不进入几微数据库；读取结果仍交给网页层现有预览和确认流程。
- P1 现在只做架子和本地验证；Windows 封装等用户确认 PC UI 后再开始。

> **阶段划分原则**：M0 是**垂直切片**（每层都碰、都跑通、但都只做最少），M1 才是**把课表做完整**。
> 这样第一周就能验证"模型 → 存储 → 渲染"整条链路，架构问题早暴露，而不是等全部写完才发现。

### 产品判断：先做“今天工作台”，再增加模块

几微优先解决三个问题：信息分散、优先级不清、临时变化容易遗漏。用户打开应用后，应先看到今天和下一步要做的事。每个新模块都要说明它如何改善这个入口。

计划表示时间安排，待办表示执行视图；两者应共用一份事项数据，并共享完成状态，避免用户在两个页面重复维护同一件事。

大学生阶段优先覆盖课程、考试与作业截止时间、周期性事项、基础收支、提醒和备份。面向上班族时复用同一模型，再增加工作/生活空间、项目关联、会议和跨设备同步，不提前把所有入口塞进首页。

## M0 · 最小可用课表（目标：让你尽快真实用起来）

**你最终能做的事**：打开网页 → 建个学期 → 添几门课 → **看到周视图课表**；手机上打开同一地址也能看到；关掉重开数据还在。

### A. 地基
- pnpm workspace + TypeScript 严格模式；`web`、`shared/packages/{core,data,ui,platform}`
- Vite + React 19 + Tailwind v4 + 路由 + 深色模式骨架
- ESLint 规则：禁止 `features/*` 直接 import Dexie（接口隔离的强制执行）
- **完成标准**：`pnpm dev` 启动，控制台打印"存储已就绪、schema 版本 N"

### B. 模型与存储（**完整**，不缩水）
> 模型是全局最贵的部分，M0 一次做全，后续里程碑不再改结构、不再迁移数据。

- `@jiwei/core`：**完整的** Zod schema（`Semester`/`Period`/`Block`/`Occurrence`/`Alert`/`Note`/`Meta`）
- `@jiwei/core`：`materialize()` 与周次/日期纯函数（`expandWeeks`/`currentWeek`/`nextOccurrence`）+ 单测
- `@jiwei/data`：仓储接口 + Dexie 引擎实现 + schema 版本迁移（幂等）

### C. 课表功能（**最小**，只做能跑通闭环的部分）
- 学期：名称、起始日（第 1 周周一）、总周数
- 作息：默认一套常见作息（第 1~12 节），先不做编辑界面
- 录课：一门一门添加（名称、老师、地点、颜色、星期、起止节次、周次)
- 周视图：`TimeGrid` 网格渲染 + 左右切周
- 本地持久化
- **暂不做**：单双周/跳过周的录入界面（模型已支持，先用全周）、连堂的拖拽、表格批量编辑、日视图、调课

### D. 完成标准
- 电脑浏览器可访问，手机浏览器打开同一地址（局域网 IP）也能看到课表
- 添加的课程**刷新/重开后仍在**（本地库生效）
- `materialize()` 与周次计算有单测覆盖
- 断网状态下页面仍能打开（本地优先的初步验证）

## M1 · 课表完整版

**功能（在 M0 基础上补齐）**
- 修改已有课程（点课程块进入表单，改完保留原 id）
- **新建与管理课表**：建多个学期/课表，能切换、重命名、删除；每张课表各自的课程与作息互不干扰
- 课程录入补全：单双周、跳过指定周、连堂（起止节次跨多节）、复制周次
- 表格/批量编辑：一屏内改多门课
- **日视图**：手机默认；"今天"卡片显示当前/下一节课
- **当前周高亮**
- 调课/停课（`Adjustment`）：某一次课临时取消或改到别的日期/节次
- 作息时间表编辑界面

**架构要求**
- 网格用 `@jiwei/ui` 的通用 `TimeGrid`（不是课表专用）
- 页面来自 `features/timetable` 导出的 `FeatureModule`，外壳负责导航
- 所有时间计算调用 `@jiwei/core/materialize`，模块内不出现日期算法

**完成标准**
- 真实学期课表（含单双周、跳过周、连堂、调课）显示正确
- 单双周、跳过周、连堂、调课都有单测覆盖
- 多张课表并存时，切换课表不会串课、删除课表不会残留数据

## M2 · 手机可用与可靠性

- PWA 安装说明、离线状态、持久化存储与用量提示；字号/密度设置。
- 当前已完成首页、课程表、安装/离线提示、字号和课表密度；启动时会申请持久化存储，设置里可查看存储状态和用量，构建产物支持离线打开。
- 当前“今天”和“课程表”是两个独立模块；计划、设置也通过底部导航进入。
- **完成标准**：手机加到桌面后全屏打开，断网可看和编辑，刷新后数据仍在。电脑浏览器和 Android Chrome 已完成本地构建验收，iPhone/iPad 真机仍需用户现场确认。

## M3 · 数据进出与课程导入

- JSON/CSV/ICS 文件进出；先做本地文件导入，不做持续订阅服务器。
- 课程表图片导入：识别只生成草稿，用户预览、修改、确认后才写入。
- CSV 模板、导入/导出、可编辑预览、重复跳过、冲突提示和事务写入已完成。
- JSON 全量备份/恢复已完成，恢复前会校验日期、引用并预计算课次；恢复后会重置当前学期和视图状态。
- ICS 导入/导出已完成：几微导出的日历可再次导入，普通日历事件会按当前作息匹配节次；无法匹配的事件会留在预览中修改。
- 课程表图片目前只支持本地预览；AI/OCR 识别按既定决定暂缓到 M8，可复用同一套草稿和确认流程。
- **完成标准**：导入失败不改变旧数据；CSV/ICS/JSON 文件能在另一台设备还原；图片识别暂不计入本阶段完成度。

## M4 · 计划与官方模块开关

- 计划统一承载截止事项、长期/无期限计划、区间任务、每周重复事项和事件/考试。
- “今天”“课程表”“计划”“待办”“记账”“笔记”“AI 助手”都是独立模块；设置页可以分别开启或关闭，关闭只隐藏入口，不删除数据。
- 当前进度：✅ 计划新增、编辑、删除、完成/恢复、逾期提示、四类计划和今天页摘要已完成；✅ 待办模块已支持截止日期、长期事项、完成/恢复和删除；记账仍待实现。
- **完成标准**：用户能记录事件并在“今天”看到；每个官方模块有独立入口和空状态。

## M5 · 待办与基础记账（核心）

- 待办：✅ 截止日、长期事项、完成/逾期、重要程度、独立入口和今天首页摘要；课程归属仍待补充。
- 记账：收入/支出、金额、分类、备注和今日汇总；先手动录入，金额用安全的十进制表示。
- **完成标准**：离线可用、可备份恢复，今天页能看见待办和收支摘要。

## M6 · 提醒与原生能力（可选）

- 应用内提醒；Capacitor 原生通知在有真机条件后验证，Web 端继续明确降级。
- 提醒模块默认关闭，开启后也不能阻塞课程表和今天页。
- **完成标准**：用户可以单独开启或关闭提醒；设备不支持通知时有清晰提示，核心功能仍可用。

## M7 · 笔记与手写（可选）

- 文字/手写/混合笔记，可关联一次课、整门课或独立保存；支持 Markdown 导出和搜索。
- 笔记模块默认关闭，开启后可单独使用文字记录，再逐步加入手写画布。
- 课程表和小票识图不属于本阶段；若后续启用 AI，识图结果仍必须先生成草稿。
- **完成标准**：课次重建后笔记引用不丢；关闭模块只隐藏入口，不删除已有笔记。

## M8 · AI、同步与受控插件（可选）

- AI 助手先支持文字意图识别，输出待确认的“添加待办/日程/支出/笔记/课程导入”草稿；默认关闭，用户明确开启后才调用模型。
- 课程表图片和小票识图共用 OCR/AI 能力层，默认优先本地处理；云端处理逐次说明用途并征得同意。
- 先验证分享和多设备同步的隐私、删除、导出、冲突和持续成本，再决定是否服务化。
- 在 L0 内置模块稳定后，试验 L1 受控插件：manifest、权限清单、数据命名空间和卸载清理；暂不运行任意远程代码。
- **完成标准**：AI 不直接写库、不绕过表单；本地核心在服务器不可用时仍可读写；未满足成本和隐私条件就保持本地优先。

### M8-A · 授权网页转计划草稿（独立可选支线，未实现）

来源：[2026-10-12 新增构想](AI网页计划与插件构想.md)。这条支线接入来源读取、轻量 AI 分析和受控插件，不改变 M0–M7 的主线顺序，也不是当前电脑适配或 APK/Windows 封装的前置条件。

| 顺序 | 后续工作 | 验收边界 |
| --- | --- | --- |
| A1 | 先定义来源、摘录和建议的契约，用假来源跑通预览 | 不访问真实网站、不引入服务器；此时只验证候选内容与确认流程 |
| A2 | 接入一个结构稳定的公开课程通知或活动报名页 | 用户主动授权；显示来源链接、读取时间和证据；读取失败不影响手动录入 |
| A3 | 提取截止日期、地点、材料，并建议少量准备任务 | 固定格式优先规则提取；AI 按需调用，生成可编辑草稿，用户确认后才保存 |
| A4 | 比较来源变化并解释对已确认安排的影响 | 不自动覆盖用户安排；保留来源和修订记录，写入可撤销 |
| A5 | 验证受控来源、分析、计划、输出插件边界 | 通过宿主接口访问数据；外部服务写入另行确认；不执行任意远程代码 |

**启动条件**：核心事项保存/完成规则稳定、导入预览和失败恢复可用，用户明确选择启动该支线。提醒与笔记输出按对应模块实际能力逐步接入；模块未实现时不承诺提醒送达或笔记保存。

**分支安排**：将来实现时使用 `feature/jw-ai-planner`，从经过验证的基线建立独立工作目录；当前只有规划记录，不创建或切换 Git 分支，不把工作区已有改动带入实验。每步仍遵循“代码 → 检查 → 用户体验并确认 → 封装 → GitHub”，支线通过验证和用户确认后才合入主线。

**暂缓项**：登录网站自动抓取、持续后台监控、云数据库、专用模型训练和无人确认写入。`Source`、`Capture`、`Suggestion` 与 `shared/packages/plugin-sdk` 均是候选设计，实施前再审查模型与权限，不提前建表或加依赖。

### M8-B · 教务系统课表连接器（第一版已接入，待学校联调）

目标是让用户在明确允许后，从自己学校的教务系统获取课表，生成预览，再由用户确认导入。它不是后台偷偷登录，也不是通用破解方案。

| 阶段 | 做什么 | 边界 |
| --- | --- | --- |
| B1 | 先支持用户填写教务系统网址，识别登录页并保存站点配置 | 不保存账号密码；不自动提交登录；只允许 http/https |
| B2 | 研究公开页面结构和学校适配器 | 每所学校单独适配；页面变化后显示“需要更新”，不盲目解析 |
| B3 | 用户在桌面隔离窗口完成登录，进入课表页后点击页面右上角“导入到几微” | 凭证只交给教务网站；几微不记录密码；只打开一个可复用窗口 |
| B4 | 读取用户点击时的课表 HTML，提取课程名、教师、教室、周次、节次和单双周 | 当前优先识别 HTML 表格；不读取成绩；动态 canvas、特殊字段和页面变化需要学校适配 |
| B5 | 生成导入预览并检查冲突 | 用户确认后才写入；重复课程、异常周次和缺失字段都要可编辑 |
| B6 | 增加 CSV/ICS/手动模板作为替代 | 学校不支持时仍能使用课程表；连接器不是核心功能前置条件 |

技术上采用“站点适配器 + 受控浏览窗口 + 纯函数解析器 + 导入预览”四层。当前已完成受控浏览窗口、用户点击按钮、HTML 表格解析和导入预览；适配器、复杂页面定位和字段映射仍需逐校补齐。解析结果先转成草稿，不直接写入 `Block`。不上传账号、Cookie 或真实课表到外部服务。

AI 提取方案见 [AI课表信息提取方案](AI课表信息提取方案.md)。当前先用规则解析和人工确认，模型接入需要单独的 provider、权限提示和费用/隐私确认。
