本轮按 **1 → 2 → 3 → 4 → 5** 完成本地实现与验证，下一步提供本地体验并按反馈修正；不把整份后续规划一次塞进近期改动。第 2—3 项合起来完成 N2 的首个闭环，第 4—5 项覆盖 O2 的基础体验，不能因此宣称完整对象系统或复杂执行安排已完成。

底层维护随对应功能一起做：复用现有服务/引用/事务接口，只补新业务所需契约；接触到的主入口装配可适量拆分。已有插件迁移不重做，模板、诊断及进一步性能优化不作为近期功能的前置大工程。

## 独立分支：UI 优化与交互优化

**负责人：用户主导重新设计。状态：待用户提供设计方案，未开始界面实现。** 这是与功能开发并列的设计工作分支，不在本次创建 Git 分支或改动现有界面。

| 任务 | 范围 | 当前安排 |
| --- | --- | --- |
| UI 优化 | 页面布局、信息层级、字号与间距、颜色、组件及弹窗的视觉统一 | 由用户重新设计；开发侧按需整理现状和实现约束，不自行确定新方案 |
| 交互优化 | 导航与跳转、表单操作、展开/收起、状态反馈、键盘与滚动、轻量过渡 | 由用户确定操作流程与交互规则，再转为具体开发任务 |

推进顺序：用户设计 → 明确改动范围 → 按确认方案实现 → 用户体验与验收。设计资料可逐步补充页面草图、关键操作流程和组件规则，不预设工具或交付形式。与该分支无关的功能开发可继续；涉及重新设计的页面改版先等用户方案，实际阻断使用的问题仍可单独修复。

实现时默认保留已有业务功能、数据兼容与插件接口；确需同步调整的内容另列范围。每次只验证受影响的页面与交互，完整检查仍留到较大交付节点。当前任务只登记计划，不代表设计已定稿、界面已优化或授权打包发布。

## 每步共同的验收条件

- 在课程、事情、待办和相应视图间跳转，能说明为什么做、属于谁、什么时候投入和何时截止。
- 同名课不会误合并，同一事情不会因多入口/多时间段而重复完成、重复统计。
- 上课结束不完成作业，步骤完成不自动等于成果交付，调课不改作业截止。
- 独立待办继续可用；原 ID、日期、周次、重复完成、阶段、来源和备份均保留。
- 删除/归档、关闭模块、重开、清缓存、复制 data 和恢复失败都有明确且无损的行为。
- 笔记不强制变任务，正文和草稿可离线保留；关闭插件不丢正文/引用，恢复包含未知或已关闭的命名空间。
- 插件通过版本化服务协作，提交后才通知；禁止跨模块读私有存储/操纵 DOM，卸载清理监听、按钮和后台任务。

详细示例见[对象与事情设计](product/对象与事情设计.md)，工程契约见[对象关联与迁移](design/对象关联与迁移.md)。

## 开发与交付顺序

设计与范围 → 代码和验证 → 本地体验 → 用户反馈 → 用户确认后封装 → 验证成品 → 获授权后提交/发布。设计文档完成不等于关联功能已实现；当前任务不授权打包、推送或修改既有 Release。

移动端、平台适配、AI、同步等长期方向继续保留在历史路线和研究资料中，推进前重新核实。外部插件仍排在 A3；当前不安装 Harness/Cordis，也不因规划授权抓取聊天、迁移真实资料或发布。
